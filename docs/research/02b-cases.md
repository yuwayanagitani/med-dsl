# R2b：変化の例・反例の台帳

作成日：2026-10-18。状態：机上の研究例。すべて架空であり、医学的基準・外部コードの正確な定義・実行結果を表すものではありません。[R2b 本文](02b-change-model.md) の C は変化の分類、I は不変条件を指します。

## 論理的な保存と合成

以下の小例は、非空の台集合を持つ通常の一階述語論理として読める範囲で考えます。`A`・`B`・`N` は単項述語、`r` は二項関係、`a` は個体です。`⊑` は集合の包含を表します。医学的事実を推論する規則ではありません。

| ID | 変更・比較 | 期待する判断 | 対応 |
| --- | --- | --- | --- |
| K01 | 定義 `A ⊑ B` を変えず、意味論に関与しない日本語表示名だけ変更する | 旧語彙での結論は同じ。表示名の同一性と概念の同一性は別に確認する | C1／I1・I3 |
| K02 | `T₀={A ⊑ B}` に、新しい述語 `N` の公理 `N ⊑ A` を追加する | `N` を空集合と解釈すれば旧モデルを拡張できるため、この条件では旧語彙の意味を保つ。`N` が非空との追加条件や新データは別に扱う | C2／I3 |
| K03 | `T₀` は `A`・`B` を宣言するだけとし、新しい `N` を使って `A ⊑ N` と `N ⊑ B` を追加する | 新たに `A ⊑ B` が導ける。旧側には `A` が真で `B` が偽の個体を持つ反例モデルがある。新しい名前だけを使った拡張でも旧側への影響はある | C2・C3／I3 |
| K04 | `T₀` に `A`・`B` だけを宣言。拡張 E は `A ⊑ N`、拡張 F は `N ⊑ B` を追加し、同じ新しい `N` を共有する | E 単独は `N=A`、F 単独は `N=空集合` で旧モデルを拡張できる。一方、併用すると `A ⊑ B` が導ける。個別の安全性の結果を、そのまま併用の保証にできない | C3／I3・I6 |
| K05 | `T₀={A ⊑ ∃r.B}` と、同じ語彙を宣言するだけの `T₁` を、`D={A(a)}` で比較する | 個体 `a` についての `B(a)` はどちらからも導けないが、`∃x B(x)` は旧側だけから導ける。個体名付きの単純な回答だけでは問い合わせの差を見落とす | C5／I3 |

K02〜K04 は本プロジェクトの小さな導出です。K05 は [Konev ほか、2012、§3 Example 8](https://arxiv.org/abs/1401.5850) の区別を参考に、比較する入力と問い合わせを明示した机上例です。一般の拡張判定アルゴリズムを検証した結果ではありません。

## 定義・文脈・記録が変わる場合

| ID | 変更・比較 | 保存することと意図して変えること | 対応 |
| --- | --- | --- | --- |
| K06 | 旧定義の病型 `P` を、新定義の `P₁` と `P₂` に分割する。旧記録には分割条件がない | 旧記録と旧 `P` の解釈を保つ。現在の条件でどちらかに確定できるとはしない。分割関係と追加情報の必要性を記録する | C5／I1・I2・I4 |
| K07 | 時点 t₁ に A が疑いと記録し、t₂ に B がその疑いを否定する | 両方の主張、対象時点、出典、確認状態を残す。現在の採用判断は更新し、疑いが現在も確認済みという結論を出さない | C6／I2・I4・I5 |
| K08 | 「家族に所見 X がある」という記録と「本人には X がない」という記録を扱う | 対象者を保つ。X の文字列だけで本人について矛盾とせず、家族の肯定を本人の肯定へ転用しない。同一対象・同一時点の食い違いは別の衝突例とする | C6／I5 |
| K09 | 二つの検体・二つの検査法・二つの結果がある記録を、属性の一覧へ平坦化する | どの検体をどの方法で測った結果かを保つ。値が全部残っていても結び付きが消えたら意味の損失。関係の事象化・役割付けで復元可能かを各設計案で示す | C3・C4／I3・I5 |
| K10 | 同じ事象に対する臨床上の分類と、地域・制度・期間に依存する会計上の分類を併存させる | 事象への参照と各分類の用途・適用条件を保つ。同じ請求分類だから臨床的にも同じという含意を追加しない | C4／I3・I5 |

K06〜K10 の期待判断は本プロジェクトの要求です。実在する概念の分割、現在の医学的判断、特定国の請求規則を確認した例ではありません。R3 で公式資料を選び、R4 で実資料に沿う場合の期待結果を別途確認します。

## 意味論・コア・利用側が変わる場合

| ID | 変更・比較 | 期待する判断 | 対応 |
| --- | --- | --- | --- |
| K11 | 新しいモジュールに、時間に依存する確率的な予測を追加する。旧利用側は確定的な属性しか扱えない | 予測対象、時間、モデル・根拠、確率の意味を定義する。数値を保存しただけで意味を理解したとは数えない。旧利用側はその範囲の解釈未対応を明示し、確定事実へ転用しない | C7／I5・I7 |
| K12 | コア新版で、未記載を「不明」と扱う規則から「偽」と扱う規則へ変更する | 旧記録で未記載だった X の否定が新たに導かれるなら、単なる構文互換と区別して意味の変更を報告する。旧解釈の再現を保つか、引き継げない範囲を示す | C7・C8／I2・I3・I7 |
| K13 | ある概念の否定を意味する未知の拡張を、古い消費側が読み飛ばす | 無視した肯定を確定出力したら失敗。影響範囲の処理を保留する等、用途に応じた扱いを示す。原データの丸ごと保存は解釈対応の成功と別集計にする | C3・C8／I5・I7 |
| K14 | 接続先の変更で新たに測定方法の入力が必須になるが、原記録・既存操作にはその情報がない | 既存の文脈から取得できるかを確認し、取得できなければ不足とする。AI やライブラリが観察していない値を埋めて「操作変更なしで対応」としない | C4・C8／I5・I8 |

K13 には [FHIR R5 の modifier extension](https://hl7.org/fhir/R5/extensibility.html) に、無視すると解釈に影響する拡張を区別する先例があります。このケースの期待動作を、そのまま FHIR 適合性の判定とはしません。

## 比較と反証の手順

R4 で再現できる評価例へ具体化するときは、各 ID に以下を付けます。

1. 言語・意味論、旧定義、新定義または拡張、依存先の版、個別データ。
2. 保存する語彙・問い合わせ・データ範囲と、意図して変える範囲。
3. 期待する含意、導けない内容、差を示す反例モデルまたは問い合わせ。
4. 導出・出典・確認者、全称的に示した性質か有限例での確認か。
5. 各設計案 A・B・C の表現、追加定義、変更箇所、未対応・保留の理由。

少なくとも、K02 の正例と K03 の反例、K04 の併用、K05 の問い合わせ範囲、K06〜K08 の訂正と文脈、K09 の関係、K11〜K14 の能力変更と不足情報を共通の比較項目にします。全項目を「保留」で通過しても成功とはしません。意味を定義できた範囲、保存を示せた範囲、残る不足を別々に報告します。

これらは設計時に参照する例なので、未知のケースへの性能を測る評価セットにはそのまま数えません。R4 で別の例・派生条件を用意し、根拠のない確定と意味の取り違えを個別に記録します。
