# R2b：変化・不変条件・拡張原理

調査日：2026-10-18。状態：基礎調査と評価方針の整理を完了。以下は研究上の作業定義・設計候補であり、MedDSL の仕様採用、実装、永続性の証明は未完了です。

[最終目標](../vision.md) は、未来永劫、原理的に変化に耐えうる医療コード体系の確立です。本調査は体系そのものを対象とします。コード移行での情報損失・追加の計算は、この原理を使う中間用途です。出典の版・確認箇所・未確認事項は [調査記録](02b-sources.md)、具体的な反例は [ケース台帳](02b-cases.md) に分けました。

## 調査から得た方針

研究の中心を、**新しい意味を定義する仕組みと、その追加・訂正が何を変えるかを明示する契約**に置きます。概念を増やすだけで受け止められる変化と、意味を記述する言語の能力まで変える必要がある変化を区別します。

先行研究には、旧語彙への影響を扱う保守的拡張、用途に応じた論理差分、論理体系を抽象化する institution、知識の撤回・改訂を扱う理論があります。一方、これらを組み合わせた医療体系の構成や、任意の将来の意味を取り込めることは、今回の資料確認では確立していません。[論理差分](https://arxiv.org/abs/1401.5850)、[institution の原著](https://courses.grainger.illinois.edu/cs522/sp2016/InstitutionsAbstractModelTheory.pdf)、[知識改訂の原著抄録](https://doi.org/10.2307/2274239)

今回決めるのは、変化の分類、不変条件の候補、三つの設計案、反例と比較手順です。固定コア、拡張可能なメタモデル、改訂可能なコアのいずれを採用するかは R5 に残します。

## 1. 「変化」を何に分けるか

以下は本プロジェクトの分類です。一つの更新が複数行に該当することもあります。医学的な具体例は説明用で、診断基準や既存コードの実際の改訂を主張しません。

| ID | 変化 | 例 | 最初に問うこと |
| --- | --- | --- | --- |
| C1 | 表示・表記の変更 | 同じ概念の別名、翻訳、画面表示 | 意味に関与する定義も変えたか |
| C2 | 既存の表現能力内で概念を追加 | 新しい病型、薬剤、検査対象 | 旧概念の結論へ意図しない影響があるか |
| C3 | 属性・関係・制約の追加 | 検体、測定方法、投与経路、複数の参加者を持つ処置 | 役割・単位・同じ事象への結び付きを定義できるか |
| C4 | 領域・目的・地域の追加 | 所見に加えて会計・研究上の分類を導入 | 一つの目的の分類が臨床上の同等性へ混入しないか |
| C5 | 概念定義・知識の改訂 | 旧概念の分割、条件の修正、従来の包含関係の撤回 | 保存する旧解釈と、意図して変える結論は何か |
| C6 | 個別の主張・記録の変更 | 疑いから確認へ、後の否定、誤記訂正、見解の不一致 | 誰がいつ述べた内容と、現在採用する判断を分けられるか |
| C7 | 意味を表す能力の変更 | 新しい時間演算、確率的な主張、従来にない関係の意味 | 既存言語への意味を保つ定義があるか、新しい意味論が必要か |
| C8 | コア・実装・外部接続の変更 | パーサー、推論器、コア規則、記録・会計システムの更新 | 構文、解釈、検証、操作のどの互換性が保たれるか |

C3 と C7 の境界は設計案ごとに検証します。例えば、複数者の関係を「事象と役割」に分解できても、分解前後で誰と何が結び付くかを保てなければ十分な表現とは数えません。新たな文字列や識別子を受け付けるだけでも C7 を解決した扱いにはしません。

体系の定義 `T`、個別記録 `D`、表示名、外部への対応規則、用途に応じた採用判断を別々に扱います。`D` に新しい観察が増えて検索結果が変わることは通常の更新であり、`T` の拡張だけで旧記録の解釈が変わることと区別します。

## 2. 一次資料から何を使えるか

### 保守的拡張と、用途に応じた意味の比較

保守的拡張は、新しい定義を加えても、指定した旧言語で言える結論が増えないことを形式化する入口です。モデルを保つ拡張と、指定した文の含意を保つ拡張は区別されます。また、概念の包含関係が同じことと、個別データへの問い合わせ結果が同じことも、一般には同じ条件ではありません。[Jung ほか、2017、導入](https://arxiv.org/abs/1705.10115)、[Konev ほか、2012、§3](https://arxiv.org/abs/1401.5850)

本プロジェクトへの含意は、互換性を「旧コードが読める」の一語で済ませず、旧語彙、個別データ、問い合わせの種類、対象用途まで指定する必要があることです。個別の変換で保持したい情報も、この比較範囲を先に定めてから測ります。

### 拡張の安全性には十分条件を使う方法がある

Cuenca Grau ほかは、オントロジーの保守的拡張・安全な再利用・モジュールを扱い、一般的な判定が困難な範囲に対して locality による十分条件を提示しています。十分条件を満たす場合の保証と、それを満たさない場合に危険だと断定することは別です。[2008 年原著、導入・貢献一覧](https://www.cs.man.ac.uk/~horrocks/Publications/download/2008/CHKS08a.pdf)

設計候補では「拡張規則に従って構成すれば、保存を示せる」仕組みを比較します。その規則では扱えないが妥当かもしれない拡張には、反例探索や個別の証明を用意します。今回 locality の具体的な判定器や証明は実装・検証していません。

### 論理を固定しない比較の枠組み

Goguen・Burstall の institution は、語彙、文、モデル、充足関係と、それらの間で表記を移す際の整合条件を抽象化します。これにより、表記の変更と意味の整合を別々に記述する視点が得られます。[1992 年原著、§2.1、Definition 1](https://courses.grainger.illinois.edu/cs522/sp2016/InstitutionsAbstractModelTheory.pdf)

ここから「将来の論理も扱うため、意味論とその接続条件を明示する」設計案 B を立てます。ただし、この抽象枠組みを名乗るだけでは、新しい医学概念に適切な意味論があること、異なる論理の接続が意味を保存すること、機械判定できることは示せません。§2.1 の同一枠組み内の語彙変更を、任意の論理間変換の保証に一般化しません。

### 情報モデル・拡張・来歴の設計から学ぶこと

openEHR は、安定した参照モデル、再利用する領域定義、用途別テンプレートを分けます。FHIR R5 は通常の拡張と、無視すると解釈に影響する modifier extension を分け、未知の modifier の処理を規定します。これらは、領域拡張や古い利用側の扱いを設計する先例です。[openEHR BASE 1.2.0、§4.1](https://specifications.openehr.org/releases/BASE/Release-1.2.0/architecture_overview.html)、[FHIR R5 Extensibility、§2.1.5.0.2](https://hl7.org/fhir/R5/extensibility.html)

OWL 2 の版 IRI は参照する定義を特定する仕組み、PROV-O の改訂関係は由来を記録する仕組みとして参考になります。本研究では、どちらも意味の保存を判定する規則とは別に設計します。[OWL 2 Structural Specification、§3.1–3.4](https://www.w3.org/TR/2012/REC-owl2-syntax-20121211/)、[PROV-O、wasRevisionOf](https://www.w3.org/TR/2013/REC-prov-o-20130430/#wasRevisionOf)

## 3. 保ちたい性質の作業定義

以下は採用済みの実装仕様ではなく、R4・R5 で設計案に要求する評価契約の候補です。意味の形式化、資料の保存、運用上の責任を分けて評価します。

| ID | 性質 | 成立を確認する条件・破れる例 |
| --- | --- | --- |
| I1 | 参照の安定性 | 同じ識別子・定義版・依存先から同じ定義を解決できる。表示名の変更で別概念にならず、廃止 ID を別の意味へ再利用しない |
| I2 | 過去の解釈の再現 | 原記録、当時の定義・規則・依存先を指定して当時の解釈を再現できる。現在の定義への自動置換は別操作にする |
| I3 | 保存を宣言した範囲の不変性 | 保存対象の旧語彙・問い合わせ・データ条件を明記し、拡張前後でその結論が一致する |
| I4 | 意図した改訂の明示 | C5・C6 では、置換・撤回・分割の理由、時点、対象、影響を保持し、旧主張を現在の採用判断へ混入させない |
| I5 | 文脈と根拠の保持 | 対象者、時間、否定、確度、観察・導出・AI 候補・人の確認、情報源を区別する。未知を否定や確定へ補わない |
| I6 | 拡張の合成に関する契約 | 依存するモジュール、名前空間、意味論、衝突条件が分かる。単独で安全な二拡張の併用も別に確認する |
| I7 | 解釈・検証能力の明示 | 利用側がどの範囲を理解・検証できるか分かる。未対応の意味を読み飛ばして完全適合と報告しない |
| I8 | 実装・操作からの意味の独立 | 別実装や臨床ライブラリでも、同じ定義と確認範囲で同じ意味を扱える。画面操作や AI の出力だけを意味定義にしない |

I1・I2 の再現には、版番号に加えて参照資料・依存先の実体を利用可能にする保存方針が必要です。識別子があるだけで、将来もアクセスできるとはしません。I5 の情報が元から記録されていない場合は、欠落を記録し、復元済みとしません。

## 4. 保存・改訂・比較をどう形式化するか

### 4.1 まず比較の範囲を固定する

`L` を意味論を定めた言語、`Σ` を概念・関係などの語彙、`T` を定義・公理、`D` を個別データとします。`T ⊨ φ` は、採用した意味論で `T` から文 `φ` が含意されることです。以下は机上の作業定義で、MedDSL の文法や内部形式ではありません。

同じ `L` の下で `T₀ ⊆ T₁` とする追加について、旧語彙 `Σ₀` で書ける指定範囲の文すべてで

```text
T₀ ⊨ φ  ⇔  T₁ ⊨ φ
```

が成立することを、まず保存の条件として調べます。対象を全旧言語の文にするか、包含関係などに限るかで保証が異なります。モデル保守性を要求する場合は、`T₀` の各モデルを、旧記号の解釈と台集合を変えずに `T₁` のモデルへ拡張できることを別に求めます。[保守性の二つの定義](https://arxiv.org/abs/1705.10115)

個別データを扱う場合は、問い合わせ集合 `Q` と旧データの許容範囲 `𝒟` を定め、

```text
すべての D ∈ 𝒟、q ∈ Q について
Ans(T₀, D, q) = Ans(T₁, D, q)
```

を比較条件の候補とします。`Ans` は選んだ言語・意味論における問い合わせの回答です。目の前の一つの `D` で一致したことと、すべての `D` で一致することは分けて報告します。`T₁` で都合が悪くなった旧データを、黙って `𝒟` から除外しません。整合性・概念の充足可能性も確認し、矛盾からの含意を正常な一致に数えません。包含関係だけの検査を問い合わせ互換と同一視しない根拠は [論理差分の §3](https://arxiv.org/abs/1401.5850) にあります。

### 4.2 回数に依存しない保証の入口

本プロジェクトの簡単な導出として、`L`・`Σ₀`・`Q`・`𝒟` を固定し、各更新 `Tᵢ → Tᵢ₊₁` が上記の回答一致を満たすと仮定します。等号の推移性から、任意の有限回 `n` について `Ans(T₀,D,q) = Ans(Tₙ,D,q)` が成り立ちます。基底 `n=0` と、各段階の一致をつなぐ帰納法による条件付きの性質です。

これは、有限個の例でたまたま動いたという根拠とは異なり、更新の回数に依存しない契約を研究する出発点になります。ただし、各更新が実際に契約を満たすこと、新しい表現を意味付きで取り込めること、`L` を変更した際の接続、無限列の極限の扱いは、この導出では示していません。将来を受け止めるには、保存対象の不変性と、新しい意味を定義できる能力の双方が必要です。

### 4.3 定義や知識を訂正する場合

C5・C6 に常に I3 の結論一致を要求すると、誤った判断を訂正できなくなります。知識の撤回・改訂自体を扱う理論は既にありますが、本調査で確認した AGM 原著は抄録までであり、医療記録への具体的な改訂演算は未選定です。[Alchourrón・Gärdenfors・Makinson、1985](https://doi.org/10.2307/2274239)

本プロジェクトでは、旧定義・主張を残す履歴と、現時点の用途に応じて採用する見解を分ける候補を比較します。例えば「時点 t₁ に担当者 A が疑いと記録」「時点 t₂ に担当者 B が否定と判断」は、それぞれの主張として保持します。どの内容を現在の確定事項へ採用するかは、出典の優先関係・対象時点・確認状態を指定する別の判断です。

`T₀` と改訂後の `T₁` について、指定した `Q` の含意が減った範囲と増えた範囲を、それぞれ差分として扱います。結論が導けなくなったことは、その否定が導けることと同じではありません。保存を宣言する部分と意図して変える部分を明記し、全体を保守的拡張と呼びません。疑い・確認・否定・誤記などを区別する先例として [FHIR R5 Condition.verificationStatus](https://hl7.org/fhir/R5/condition-definitions.html#Condition.verificationStatus) を参照します。

異なる主体の主張を、そのまま一つの無文脈な真偽集合に投入する設計も避けて比較します。主張を文脈付きで表す方法、矛盾を隔離する推論方法、採用判断を外で行う方法のどれを使うかは R5 の課題です。来歴の記録だけでは、この採用判断は定まりません。

### 4.4 言語やコアが変わる場合

異なる言語へ表現を移すなら、文の変換 `e` と、新しい側のモデルを旧側として解釈する対応 `r` を定め、例えば以下の条件を検討します。

```text
新しい側のモデル M′ が e(φ) を満たす
  ⇔ r(M′) が旧側の φ を満たす
```

これは institution の充足条件を参考にした研究上の要求案です。異なる論理への適用には、対応の構成、対象モデルの範囲、旧側のモデルを十分に表せるかも個別に検討します。式を掲げるだけで適切な変換が存在するとはしません。[参考にした定義](https://courses.grainger.illinois.edu/cs522/sp2016/InstitutionsAbstractModelTheory.pdf)

元のバイト列を読み戻せることと、この意味の対応は別に評価します。さらに、医学的に意図した概念をそのモデルが捉えているかは、形式内の整合条件に加えて、資料と専門的な確認を必要とします。

## 5. 比較する三つの設計案

以下は先行資料から立てた本プロジェクトの候補です。製品の機能比較でも、完成済みの形式体系でもありません。併用も可能ですが、まず同じケースでそれぞれの限界を確認します。

| 観点 | A：固定した基礎言語＋領域定義 | B：意味論を拡張できるメタモデル | C：コアの改訂と意味の引き継ぎ |
| --- | --- | --- | --- |
| 固定するもの | 構成子と意味論。領域語彙・定義を追加する | 語彙・文・モデル・充足関係等を記述し接続する契約 | 各コア版の意味と、版間で満たす引き継ぎ契約 |
| 新しい意味の導入 | 基礎言語で定義し、保存対象への影響を示す | 新しい意味論・機能と旧側への接続条件を定義する | 新版を定義し、旧側からの変換・旧解釈の扱いを明記する |
| 有利と考える点 | 拡張規則と共通検証器を絞りやすい | 既存言語で定義できない意味の導入を研究できる | 基礎の誤りや表現能力不足に対して改訂を明示できる |
| 中心的な仮定 | 必要な将来の意味が基礎言語で適切に定義可能 | 新しい意味論を記述でき、必要な接続・合成条件を示せる | 必要な意味の引き継ぎが存在し、依存版と解釈を維持できる |
| 壊れ方 | 自由記述や未解釈データを「対応済み」と数える。表現不能な意味が出る | メタモデル自体の限界、接続条件の不足、意味論の組合せで保証が崩れる | 非可逆な変換、連鎖での劣化、旧解釈の消失。版管理だけで目的を達成したと見なす |
| 必要な根拠 | 定義的な拡張の十分条件、表現できる範囲、反例 | 意味論の記述例、接続と合成の条件、既存側を保つ証明 | 各段階と合成した引き継ぎの保存条件、損失の明示、再現性 |
| 次に試す例 | 新属性、複数者の関係、独立拡張の併用 | 新しい時間・確率の意味、旧利用側での扱い | 定義訂正、コア規則の変更、二段階の引き継ぎ |

A を「現在の病名一覧を固定する案」とはしません。B も無制約なプラグイン機構とはしません。C では変更可能な境界を認める一方、版を増やすだけで何を保存できるか不明な設計を合格にしません。三案とも、新しい意味の定義と、保存・意図した改訂の説明を求めます。

現段階では A を比較の出発点、B を表現能力を広げる候補、C を基礎の改訂を扱う候補として並べます。A で十分だという証拠も、B・C を足せば全将来変化を網羅するという証拠もありません。

## 6. 表現の広さと機械判定を分ける

OWL 2 Profiles は、表現を制限して特定の推論課題を効率化する設計を示します。ただし、通常の推論課題が決定可能であることから、保守的拡張の判定も決定可能とは言えません。Jung ほかは、充足可能性が決定可能な FO²・GF においても、論文の定義する保守的拡張は決定不能となることを示しています。[OWL 2 Profiles、§1・§5](https://www.w3.org/TR/2012/REC-owl2-profiles-20121211/)、[2017 年原著、§1](https://arxiv.org/abs/1705.10115)

この結果は特定の論理・問題に関するものであり、MedDSL の最終目標の不可能性を証明するものではありません。何を機械的に完全判定するか、そのためにどんな制約を置くかを、設計案ごとに決める必要があります。

| 課題 | 明示する範囲 | 未解決の場合の扱い |
| --- | --- | --- |
| 構文・型・参照の検証 | 文法、型、必須参照、依存版 | 入力不正と意味論未対応を区別する |
| 制約への適合 | 対象プロファイル、入力の完全性、制約言語 | 適合した制約だけ報告し、医学的正しさへ一般化しない |
| 推論・問い合わせ | 言語断片、意味論、入力条件、推論課題 | 未実装、情報不足、資源制限を分ける |
| 拡張の保存判定 | 旧語彙、問い合わせ、全データか特定データか、十分条件 | 十分条件を満たさないだけなら不適合と断定せず、判定保留にする |
| 差分の提示 | 比較言語、方向、差の証拠、列挙範囲 | 反例が見つからないことと、差分が存在しない証明を区別する |
| 医学的な妥当性 | 出典、専門的確認、対象用途 | 型が正しくても医学的に確認済みとはしない |

処理結果は、支持できる結論、反例・不適合、情報不足、機能未対応、計算を完了できない状態を区別する案とします。これを新しい真理値論理の採用とは見なしません。タイムアウトは、入力が偽である証拠でも、その入力について決定不能と証明した結果でもありません。

## 7. 反例と評価の組み方

[ケース台帳](02b-cases.md) に K01〜K14 を用意しました。外部マスターを使わない架空例で、通常の拡張、意図的な訂正、誤った合成、文脈の消失、表現能力の追加、操作と情報不足を含みます。これは人が読める研究用の問題設定であり、実行したテストや最終評価データではありません。

R4 では各ケースに入力定義、変更、保存対象、期待する結論・反例、根拠、確認者を付け、R5 の各案を同じ条件で比較します。代表例に合わせただけの過適合を避けるため、新しい名前への置換、属性・参加者数の増加、拡張の順序交換、依存先の版差、訂正の連鎖を派生条件にします。

| 評価軸 | 残す証拠 |
| --- | --- |
| 意味の表現 | 形式定義と、何を表せて何を表せないか。未解釈保存を別集計する |
| 保存・改訂 | 契約の仮定、証明または反例、指定した問い合わせの結果 |
| 拡張の合成 | 依存関係、衝突、単独時と併用時の差、順序の影響 |
| 機械的な判定範囲 | 完全な判定、十分条件のみ、有限例のみ、未対応の内訳 |
| 実装間の再現 | 同じ意味論・資料での結果一致。実装をまだ比較していなければ未実施 |
| 保守・臨床利用・AI | 拡張時に変える箇所、追加情報の必要性、確認負担、出典と確認状態の保持 |

根拠は「先行研究の性質」「MedDSL 案についての証明」「机上の反例」「実行例」「実利用の評価」に分けます。本調査にあるのは、先行資料の限定的な確認、作業定義、簡単な条件付き導出と机上例です。推論器の実行、形式証明支援系での検証、医療者による評価は行っていません。

## 8. D08 の暫定整理と次の判断

2026-10-18、D08 の研究方針として、C1〜C8、I1〜I8、保存・改訂・言語変更を分けた評価、三案 A・B・C、ケース K01〜K14 を次段階の比較材料にします。目的 D00 は維持し、採用仕様と実現可能性は未決定です。

次に解くべき問いは以下です。

1. **意味の基礎**：概念・個別事象・主張・定義をどう区別するか。文脈・時間・確度をどの層で定義するか。
2. **拡張の原理**：どの拡張なら保存を構成的に示せるか。独立した拡張を併用するための十分条件は何か。
3. **表現能力の境界**：検査・処置・薬剤等の資料で、固定した構成子では表せない意味はあるか。新しい意味論への接続は定義できるか。
4. **知識の訂正**：履歴と現在の採用判断を分ける具体的な意味論、主張の衝突、撤回の影響をどう定めるか。
5. **計算の契約**：どの言語・問い合わせで完全な判定を求めるか。限定的な判定の出力を、利用側がどう解釈するか。

後続の [R3](03-data-access.md) で、これらを検討する資料・版・利用条件を整理しました。RxNorm CPC と FHIR の定義を初期材料に選定し、WHO・LOINC 等の内容を独自体系開発に取り込む条件は保留しています。次は R4 で評価を具体化し、R5 で意味論と設計を選びます。

保存対象・新たな意味の例・論理の条件が増えたとき、十分条件が必要な拡張を排除したとき、複数拡張の合成に反例が出たときには、この整理を見直します。比較不能を正しく返すことは必要ですが、それだけを増やして変化に耐える体系を達成したとはしません。
