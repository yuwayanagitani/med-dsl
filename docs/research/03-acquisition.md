## RxNorm の内容に関する初期確認

両アーカイブで全メンバーの CRC 検査が通り、各 README は選定した日付の CPC であることを記載していました。各 ZIP は README、三つの RRF、データベース向けの付属スクリプトを含む 16 ファイルでした。展開や付属スクリプトの実行はせず、アーカイブから直接検査しました。

| RRF | 列数（終端の区切りを除く） | 2026-09-08 の行数 | 2026-10-05 の行数 |
| --- | --- | --- | --- |
| `RXNCONSO.RRF` | 18 | 246,241 | 247,028 |
| `RXNREL.RRF` | 16 | 2,578,453 | 2,589,722 |
| `RXNSAT.RRF` | 13 | 3,370,462 | 3,382,290 |

全行について UTF-8、列数、末尾の区切り、出典欄を検査しました。出典は `RXNORM`・`MTHSPL`・`MTHCMSFRF` の範囲内でした。実際に `RXNCONSO` に `MTHCMSFRF` が各版 11 行あり、第三者の商用薬剤語彙の混入はこの出典検査では見つかりませんでした。出典別の件数は台帳にあります。三つの出典を含む CPC の説明は [NLM 技術文書 §11.6](https://www.nlm.nih.gov/research/umls/rxnorm/docs/techdoc.html) で確認できます。

この検査は、全概念の意味、関係の医学的妥当性、外部参照の解決、旧版から新版への意味の保存・喪失・追加を検証したものではありません。台帳の `content_verified` は引き続き `false` とし、ファイル検査の `initial_file_checks_passed` と区別しています。行数が変わったことから概念数の変化や意味差分を算出した扱いにもしていません。

## 再検査

Python 3.9 以降の標準ライブラリだけで実行できます。リポジトリのルートで以下を実行します。

```bash
python3 scripts/research/verify-r3-materials.py
```

台帳に今回の検査結果を記録する場合は次のコマンドです。

```bash
python3 scripts/research/verify-r3-materials.py --record
```

四つすべての初期検査が通れば終了コードは 0、ファイル不足または不合格があれば 1 です。詳細は `data/research/r3/verification-report.json` に出ます。ネットワーク通信、ZIP の展開、付属 SQL 等の実行は行いません。

公表 MD5 と不一致、または記録済み SHA-256 から変わったファイルは不合格とし、そのハッシュを台帳へ上書きしません。`--record` は合格したファイルの情報と各項目の最終検査状態を更新します。取得日時は、同じ SHA-256 を持つ取得記録がローカルにある場合だけ転記し、不明な場合は検査日時で代用しません。

確認用の架空ファイルで、正常な ZIP・HTML、MD5 不一致、記録済みハッシュの変化、CRC 不良、列数不正、範囲外の出典、異なる HTML 版、ファイル不足を区別できることを検査しました。恒久的なテスト基盤・依存パッケージは追加していません。

## 通信と保存の記録

最初は NLM 配布元の名前解決がタイムアウトしましたが、再試行で通信が始まりました。約 75 MB の ZIP は 25 秒の制限では途中で切れたため、その不完全な取得物を除き、待ち時間を延ばして再取得しました。今回の成功した取得記録と最終 URL は台帳にあります。

外部ファイル本体・取得記録・詳細レポートは `data/` の除外設定下に置き、Git には調査文書、集計メタデータ、検査スクリプトだけを残します。FHIR HTML に含まれる外部用語の参照・例を、独自体系へ転用可能な語彙データとして扱いません。[R3 の利用範囲](03-data-access.md) は維持します。
