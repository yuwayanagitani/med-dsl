## P：体系そのものの 14 ケース

K は [R2b](02b-cases.md) の ID を引き継ぎます。K01〜K05 は非空の台集合を持つ通常の一階述語論理、開世界の含意として読みます。`A,B,N` は単項述語、`r` は二項関係、`a` は個体です。`⊑` は包含。`¬` の含意と「含意されない」を分けます。K06 以降の主張・採用判断・来歴は候補方式ごとの意味定義を要し、この表をそのまま新しい論理・DSL の仕様にはしません。

K02・K04 のモデル拡張はこの有限ケースの推論とは別に、指定した全旧モデルに対する小さな導出として確認できます。K05 は [Konev ほか §3 Example 8](https://arxiv.org/abs/1401.5850) を参考にした本プロジェクトの例です。その他の臨床らしい語は研究上の架空要件で、公式の疾患定義を用いていません。

各方式の記録には `表現・意味定義・問い合わせ結果・証拠/反例・保証範囲・未対応理由・変更箇所・確認者` を必須にします。「未対応」は誤った確定を防げても、表現力の成功とは数えません。K の全件は既知の設計資料であり、未見評価にはしません。

## M：架空ケースに共通する読み方

入力体系は各行専用の `urn:med-dsl:fiction:<ID>:source@0`、出力体系は `urn:med-dsl:fiction:<ID>:target@1`。方向は source→target、用途は架空の薬剤記録の参照更新監査、地域は架空 J、言語は日本語です。CPC の実データや RxNorm の公式概念・対応規則ではありません。定義と対応根拠は各行自身（`F-<ID>@1`）です。

`p`・`q` は架空成分、`u` は同一の架空含量単位、錠・液は互いに異なる架空剤形です。含量は処方用量ではありません。例えば `{成分p,含量1u,剤形錠}` はこの例の同一事象の束です。異なる事象や成分との結合は、明示された結合だけが成立し、一覧から全組合せを作りません。

各行で示した命題・関係とその否定を問い合わせ集合 Q にします。含意は明示定義とその行で指定した規則から求め、欠落は否定ではありません。複合成分では `含量(事象,成分,値)`、記録文脈では `主張(主体,対象時点,命題,極性,確度,由来)` の結合を保ちます。同一事象・同一成分の含量はこの架空モデルでは単値です。各コードの定義は記した属性の束と同値とし、片方向の含意しかない場合はその旨を明記します。これらは評価用の記述記法で、採用する内部データ構造ではありません。

### 期待結果の共通項目

| 欄 | 共通規則 |
| --- | --- |
| 候補 | 表の `候補{…}` が許す正解集合。条件付きは条件を付けたまま返す。`候補∅` は自動確定・候補提示を許す対応がない。監査対象の不適合な出力を候補に混ぜない |
| 関係 | 入力→その候補または監査対象の関係を表のとおり判定。複数候補では各条件下で判定 |
| 差分 | `L` は喪失、`A` は新たな意味の追加、`X` は矛盾、`U` は比較不能、`N` は必要情報。表にない欄は空集合。ただし U の範囲では L/A/X は「未判定」で、空の差分を宣言しない |
| 補助情報 | `E` は入力コード以外の情報。B0 と B1 を区別。出典は行内の `H`（人の確認済み）、`AI`（未確認候補）等の指定どおり保持 |
| 明示化 | 入力の規則からすでに含意される内容を `明示化` と記録し、新しい臨床情報 A に加えない |
| 許容損失 | 明記した行以外は空集合。許容しても警告 L は必須。出力コード単体と記録全体の差を別に判定 |
| 原情報 | 全件で入力・体系版・定義根拠 F-ID を保持する。回収した原情報と出力単体の意味を混同しない |
| 確認状態 | 全件 `作成者草案／独立確認待ち／実行前`。医学的な正解確認済みとはしない |

各表の「期待結果」がケースごとの明示的な上書きです。追加の外部知識・常識・医学的判断を暗黙に足して正解を変えません。初回実行前に確認者が全ケースの問い合わせと期待項目集合を列挙し、凍結します。
