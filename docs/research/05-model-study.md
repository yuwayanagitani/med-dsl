# R5：基礎モデル・拡張・互換性の設計比較

作成日：2026-10-18。状態：一次の設計比較と D06 の研究用選定。実装、独立レビュー、R4 の実行評価、普遍性・永続性の証明は未完了です。最終目標は [vision](../vision.md) のコード体系の確立です。

## 今回の選定

**通常の拡張には A の定義追加、表現能力の追加には契約を明示した B の意味モジュール、コア自体の改訂には C の意味引き継ぎを使う構成**を、試作に向けた基礎モデルとして選びます。各案を無制限に混ぜず、どの更新をどの契約で受け入れるかを分けます。

体系の中心は、**不変な定義参照、役割を保つ概念・事象・主張、版付きの意味定義と拡張契約**です。外部コードへの変換はこのモデルの接続用途です。コード文字列の文法、パーサー、実装言語、データベースはまだ選びません。

| 決定 | 採用する研究方針 | 採用しない前提 |
| --- | --- | --- |
| 基礎モデル | 概念定義と個別事象と主張を分け、有限アリティの関係・役割付き事象を表現する | 病名・薬剤一覧が増えれば全将来の意味を表せる |
| 通常の拡張 | 同じ意味プロファイル内で定義を追加。保存の十分条件 S1・S2 を最初の認定対象にする | 新しい名前・属性なら無条件に互換 |
| 意味能力の追加 | 意味プロファイルを明示したモジュールを追加。消費側の対応能力を照合する | 文字列や任意プログラムを保存すれば意味を解釈できる |
| コアの改訂 | 旧解釈を残し、移す範囲には文・モデルの対応と保存条件を要求する | 版番号と移行スクリプトだけで意味を保存できる |
| 訂正 | 旧主張を保持し、用途別の採用判断を更新する | 古い主張を現在も真にする、最新の主張を常に正しいとする |
| 計算 | 対応断片・十分条件・未対応・打切りを明示する | 表現可能なすべての意味を一つの推論器で完全判定する |

以下は仕様の土台となる契約です。S1〜S3、C1、R1、G1、U1 の条件・手作業の導出は [原理の検討](05-principles.md)、一次資料の確認範囲は [出典](05-sources.md) に分けました。

## 三案を同じ条件で比較する

[R4](04-evaluation.md) の語彙・問い合わせ・データ・用途を共通にします。A を現在のコード一覧の固定、B を無制約な拡張、C を単なる版管理と見なす比較はしません。各案でも適切に設計すれば文脈や来歴は持てるため、その可否を案の名前だけから決めません。

| 比較項目 | A：固定言語＋領域定義 | B：意味論を拡張するメタモデル | C：コアの改訂と引き継ぎ |
| --- | --- | --- | --- |
| 意味論 | 一つの L を固定し、T を追加・改訂 | モジュールごとに L と充足・問い合わせを明示 | 各コア版の L と版間の意味対応を明示 |
| 保存対象 | 旧語彙・旧データに対する Q | 既存モジュール内の Q と、接続した範囲の Q | 移行の e/r が保存する Q、別途の旧解釈再現 |
| 通常の概念・関係追加 | 固定 L で定義できれば簡潔。S1・S2 が入口 | 同じ L 内なら A と同じ。新 L 追加は不要 | 毎回コアを変える必要はないが、版移行を標準経路にすると負担が増える |
| L 内で定義できない意味 | 既存の構成子では受け止められない範囲を認める | 新 L を定義して受入れ可能。接続・合成が追加の証明課題 | 新コアへ拡張可能。旧から新の移行と旧消費側を扱う必要 |
| 拡張の合成 | 全体の定義依存と旧語彙への影響を確認 | モジュール間の意味の整合・循環・相互作用も確認 | 段階間と全行程の保存範囲・損失を確認 |
| 訂正・履歴 | 主張と採用方針を L 内に表す必要 | 訂正モジュール間の意味・優先関係も必要 | 旧解釈を残す仕組みが必要。新版化だけで採用判断は決まらない |
| 判定・推論 | 対応する断片を絞りやすい。一般の保存判定とは別 | 異なる判定器と能力照合が必要 | 版ごとの判定器と移行契約の維持が必要 |
| 主な負担 | 基礎 L の設計と十分条件。表現境界で再検討 | モジュールの意味仕様・接続証拠・能力管理 | 旧仕様・依存実体の保存、版間証明、再検証 |
| 単独採用の残る問題 | 未知の意味が固定 L に必ず収まる根拠がない | メタモデル自身の表現限界・改訂を扱う必要が残る | 版変更のたびに新しい概念表を置くだけでは拡張原理にならない |

この比較から、通常の定義追加を小さい契約で扱いつつ、その能力を超える場合の明示的な経路も初期設計に持つ構成を選びます。これは普遍性を達成した結論ではなく、三案の未解決点を隠さず実証するための選択です。

## D06：体系の意味を構成する要素

### コードと定義参照

外部コードと独自概念を同じ識別子にまとめません。独自コードは定義を安定して参照するために発行し、コードの桁・語順へ医学的意味を埋め込むことは初期要件にしません。合成した表現も意味の単位として参照できます。医療者は将来の臨床ライブラリを通じて扱います。

| 要素 | 定める内容・不変条件 |
| --- | --- |
| 概念族の参照 | 改訂を追う系列。系列が同じだけでは版間の論理的同等性を意味しない |
| 定義参照 | 名前空間、ローカル概念 ID、定義版、意味プロファイル版、依存スナップショットを固定。既存参照を別の意味へ向け直さない |
| 概念定義 | 何を表し、どの属性・関係・制約・含意を持つか。機械的な形式と人の説明・一次根拠を対応付ける |
| ラベル | 言語・表記の版を別に持つ。ラベル変更が意味変更を伴うかを確認する |
| 外部参照 | 外部体系、版、コード、出典・権利・解釈範囲。未解釈の参照は独自定義済みの概念とは区別 |
| 定義間の対応 | 同等・広狭・排他等と方向・用途・条件・根拠。系列内外を問わず自動で同等としない |

定義・依存先の原実体とハッシュを保持します。ハッシュはバイト列の固定に使い、意味の正しさや二定義の同等性の証明にはしません。OWL 2 の ontology/version IRI は参照分離の先例ですが、MedDSL の定義参照を OWL だけへ固定する選定ではありません。[OWL 2 Structural Specification §3.1–3.4](https://www.w3.org/TR/2012/REC-owl2-syntax-20121211/)

意味が変わるときは新しい不変な定義参照を作り、系列の関係と変更理由を付けます。単なる外部コードの写しを新概念と称したり、臨床ライブラリの都合だけで概念の意味を定めたりしません。原コードだけ保存した場合は「参照保持」として別集計します。

### 個別事象・主張・採用判断

| 要素 | 必須の意味 |
| --- | --- |
| 個体・事象 | 対象者、検体、観察、処置、薬剤記録等の参照。同じ値が出ても同じ事象と推定しない |
| 関係 | 関係定義、参加者と役割、対象事象。成分と含量、検体と方法と結果の結合を保つ |
| 主張 | 内容、対象者・事象、対象時点、記録時点、主張者、肯定／否定、確度、由来、確認状態。欠落なら欠落理由を保持 |
| 由来 | 原文・原コード、観察、判断、規則導出、AI 生成候補、人の確認を区別。導出は入力主張と規則版を参照 |
| 訂正 | 訂正・撤回の対象、理由、時点、主体。履歴にあるという理由で現在の採用集合へ入れない |
| 採用方針 | 用途、対象時点、参照時点、方針版を指定して主張を選び、採用・保留・衝突と理由を返す |

主張 h に「p が真と記録された」と保持することから、p の事実を無条件には推論しません。K07・K08 の異なる主体・時点の主張を一つの無文脈な理論に投入せず、採用方針と対象範囲を指定した後の解釈を分けます。明示的な衝突が見つかれば、P0 の確定回答を停止します。一般の論理的整合性を未判定なら、その未判定も残します。

PROV の由来・改訂関係は再利用候補ですが、来歴だけで採用判断は決まりません。[PROV-O wasDerivedFrom / wasRevisionOf](https://www.w3.org/TR/2013/REC-prov-o-20130430/#wasRevisionOf)

### 役割付きの表現の小例

以下は K09 の説明用の架空表現で、DSL の文法ではありません。

| 事象 | 検体 | 方法 | 結果 | 主張の由来・状態 |
| --- | --- | --- | --- | --- |
| e1 | s1 | m1 | 陽性 | h1：測定記録、人の確認済み |
| e2 | s2 | m2 | 陰性 | h2：AI の抽出候補、未確認 |

e1/s1/m1/陽性の結合は保持します。e2 は候補記録として参照できても、観察済み・人の確認済みの事実へ昇格しません。木・グラフ・関係テーブルへの保存形式は後で選べますが、参照共有と結合を失う単なる属性集合への平坦化は選びません。

## 拡張を受け入れる手順

| 更新 | 受入れ契約 | 認定できない場合 |
| --- | --- | --- |
| 表示・説明の更新 | 意味定義と依存先を変えない。意味に不関与の条件を確認 | 意味変更の可能性を調べ、単なる表示変更と分類しない |
| 同じ L 内の新定義 | S1 の非循環定義、S2 の空でもよい下位概念から開始。全依存閉包と新記号の衝突を確認 | 別の証明、反例、十分条件を検討。条件外を直ちに危険とはしない |
| 旧定義・知識の訂正 | 新定義参照と明示的な変更関係を作り、保存範囲と意図した差を指定 | 旧解釈を残し、新しい採用を未確認として保留 |
| 新しい意味モジュール | 文・モデル・問い合わせ・対応断片・依存版と、他モジュールへの影響を定義 | 保存のみを許す範囲と解釈不可の範囲を分ける。確定出力を止める |
| コアまたはモジュール間の移行 | 文の対応 e、モデルの対応 r、対象 Q、損失と C1 の成立範囲を提示 | 無損失移行と呼ばない。旧解釈の再現と損失付き射影を別経路にする |

モジュールの宣言票には、識別子・版・意味仕様・依存参照・定義する記号・意味への影響・対応問い合わせ・資源制限・保存認定の種類と範囲・根拠・確認者を含めます。宣言票に「互換」と書いただけで認定しません。自動チェックできる構文条件と、人が確認する意味・医学的妥当性を分けます。

古い消費側は能力を提示し、必要な意味を解釈できるか照合します。未知の項目を「表示専用」と判断するには、既知の信頼できる定義や影響範囲の根拠が必要です。影響自体が不明なら該当する主張・問い合わせを保留します。E09 の既知の表示専用項目と、E10 の未知の否定かもしれない修飾を同じ処理にしません。

| K03 旧含意の追加 | 反例を示し、保存宣言しない | 新記号を介した影響も検査 | コア新版でも差を隠さない | A(a) と B(a) の差を返す。S1/S2 認定外 |

| K07 疑いと否定 | 主張と採用方針を表す | 方針間の意味も明示 | 時点ごとの方針・定義を固定 | R1。履歴は保持し採用集合を更新 |
| K08 家族と本人 | 主体・時点を分離 | 同じ主張境界の共有 | 移行でも主体を維持 | 対象者の異なる肯定・否定を衝突としない |
| K09 二観察 | 事象と役割の結合を保持 | 新しい関係の意味・役割を定義 | 事象化の読み戻しを確認 | G1。平坦化された値一覧は不適合 |
| K10 会計と臨床 | 同一事象と用途別分類を分離 | モジュール間の含意を制御 | 制度版・適用期間を保持 | 会計一致から臨床同等性を導かない |
| K11 確率予測 | 固定 L 内に意味定義できる範囲を確認 | Prob-1 の意味と能力を定義 | 新意味版から旧への射影範囲 | 対応側は予測として解釈。旧側は確定事実へ移さない |
| K12 欠落→偽 | 意味論固定なら許容更新外 | 意味プロファイル変更として扱う | 新旧の否定の差を報告 | コア/意味版を分け、旧解釈を残す |
| K13 未知修飾 | 読み飛ばしを禁止する条件 | 影響範囲と能力照合が必要 | 旧利用側での停止が必要 | 保持と解釈を別判定。肯定出力を停止 |
| K14 新必須情報 | 入力契約と取得根拠を確認 | 補助モジュールの由来を照合 | 新接続条件を既存操作と照合 | 台帳があれば出典付き取得、なければ不足。U1 |

三案のいずれも K07・K09 等を表現し得ます。選定は、特定の案だけが表現可能だと証明したためではなく、通常の更新に小さい保存条件を適用しながら、意味能力・コア変更の課題を残さない責務分担によります。

### 中間用途 40 ケースから必要になる契約

| ファミリー | 共通モデル側の責務 | 直接対応でも実現し得ること／追加負担 |
| --- | --- | --- |
| D-a 名称・参照 | 定義とラベル、体系版の照合 | 直接対応でも可能。定義保持の初期費用を比較する |
| D-b 粒度 | コード・記録全体の射影と損失 | 直接規則でも警告可能。中間表現を挟む分の二重射影も監査 |
| D-c 条件 | 候補条件・補助情報の来歴・B0/B1 | 条件付き ConceptMap が比較基準。条件を片方だけに与えない |
| D-d 状態 | 未収載、対応なし、入力不正、打切りの区別 | 表現方式にかかわらず必要。実装漏れをモデルの利点と数えない |
| D-e 主張文脈 | 対象者・時点・極性・確度 | 接続先の情報モデルを使える場合も同じ条件で比較 |
| D-f 由来 | AI 候補・確認状態・明示化 | PROV 等の再利用を比較。独自方式だけの機能とはしない |
| E-a 成分結合 | 事象・成分・含量の関係 | 直接変換でも保持可能。規則重複・新接続時の変更量を測る |

| E-c 未知の意味 | 能力宣言、意味モジュール、停止 | 各方式の未対応・追加定義・実装変更を同じ分類で記録 |
| E-d 段階変換 | 原情報、版、射影の連鎖、訂正 | 中間表現に利点があるとは事前に仮定しない。U1 を双方に適用 |

R4 の実 CPC の追跡では、名称行の差と意味の差を分離し、同一 RXCUI の参照候補にも確認範囲を付けます。片版にない ID を後継へ推定置換しません。FHIR の共通の時点型では限定した問い合わせを比較し、Timing のような能力差は型の受理と意味解釈を分けて扱います。実資料の追跡は、三案の性能差を測った結果ではありません。

| 候補 | 今回の判断 | MedDSL 側に残る責務 |

| PROV | 由来・導出・改訂の表現の再利用候補 | どの主張を現在の用途で採用するか、確認状態、衝突の裁定 |
| HAPI FHIR・ROBOT | D02 の検証候補を維持。今回インストールしない | R6 の対象機能で採用の要否を決め、利用した機能と独自部分を測る |

RDF の dataset の意味は、グラフ名が何を指すかを一律には確定しません。[RDF 1.1 Semantics §10](https://www.w3.org/TR/2014/REC-rdf11-mt-20140225/#rdf-datasets)。SHACL も要求された推論方式に対応しない場合の failure を区別します。[SHACL §1.5](https://www.w3.org/TR/2017/REC-shacl-20170720/#entailment)。これらを踏まえ、保存形式や検証ツールを選んだだけで、主張の意味や完全な意味比較を実現した扱いにはしません。

この責務分担の組合せが既存研究にないという独創性は、まだ主張しません。最終目標に対して既存原理をどこまで再利用できるかを試作で確認します。WHO・LOINC 等の取り込みの保留は D03 のままです。

## 計算・出力の契約

最初に完全な処理を目指す範囲は、有限の役割付き記録、主張の参照と採用方針、非循環の定義展開、指定した有限問い合わせの比較です。一般の保存判定を毎回完全に解く方式ではなく、S1・S2 を満たす更新を認定する手順から始めます。認定外の更新は範囲付きの反証・個別証明・未判定として扱います。

| 境界 | 出力に必須の内容 |
| --- | --- |
| 定義・拡張の受入れ | 定義と依存版、受理/拒否/未認定、認定方式、旧語彙・Q・D、証拠、影響範囲 |
| 主張の採用 | 使った主張・方針、対象/参照時点、採用/保留/衝突、根拠と不足情報 |
| 意味の問い合わせ | 含意/明示的反証/未決、衝突、未評価理由。未決と未実装・打切りを混同しない |
| 外部への移行監査 | R4 の候補集合・意味関係・L/A/X/U/N・B0/B1・出力単体/全体・根拠・処理状態 |
| 臨床ライブラリ | 操作が提供した事象・主張と由来、接続先の必須条件、不足情報、確認状態。素のコードの入力を必須にしない |
| AI | 定義・役割・対象時点・根拠を取得する経路と、AI 生成候補を提出する経路を分ける。生成は人の確認済み状態を付与できない |

確度・確認状態の更新には根拠を要します。単なる構文上の適合は確認根拠になりません。意味プロファイルを増やしても、すべての接続先や古い AI が自動的に理解できるとはしません。

## 選定の根拠と限界

形式面では S1・S2 の構成による保存、有限回合成の S3、モデル被覆まで要求する C1、履歴と採用の分離 R1、喪失の回復限界 U1 を整理しました。C1-a では、型付き四項関係から役割付き事象への変換について、文の対応・モデル被覆を具体的に構成しました。これらは条件付きの手作業の導出です。S1 で認定される全式を P0 が計算できるとは限らないため、保存認定と推論能力も別に宣言します。

実証面では R4 の実資料の部分追跡と、K/D/E への机上対応までです。異なる実装間での回答一致、40 件の実行、医療者の負担、未見版・未見体系への適応性は未確認です。

永続性に対する残る中心課題は、新しい意味に適切な定義が作れる範囲、モジュール間の接続と合成、C1-a を越えた異なる意味プロファイル間の引き継ぎ、原実体の長期保存・解釈の再実装です。今回の選定を「版管理できるから未来永劫対応」とはしません。

### D06・D08 と見直し条件

2026-10-18、D06 の研究用基礎モデルとして本構成を選定し、D08 の初期保存原理に S1・S2・S3、改訂・引き継ぎの契約に R1・C1 を置きます。完全な形式仕様・最終採用・実装の適合は未確定です。

次の場合は設計を見直します。

1. 役割付き事象・主張で必要な意味を表せず、未解釈保存だけが増える。
2. 通常必要な拡張の多くが認定条件から外れ、証明・確認負担が実用にならない。
3. 旧解釈の再現はできても、新しい意味との関係が定められず原理上の課題を先送りする。
4. 接続先追加でコアや医療者の操作を毎回変えなければならない。
5. 直接対応・既存情報モデルとの同条件比較で、追加費用に見合う効果を示せない。

その場合も最終目標は維持し、表現、十分条件、モジュール境界、実験条件を再検討します。次は R6 で、G1 の関係保持、R1 の履歴、S1/S2 の認定を中心とした小さい試作の入出力・対象ケース・実装構成を定めます。P0 だけの試作を R4 全体の合格としないことも着手条件に入れます。
