## 実装した範囲

| 部分 | 動作 |
| --- | --- |
| `check_extension` | 旧側と追加側をハッシュ付き依存閉包で解決し、S1/S2 の十分条件を検査。旧語彙、新記号、依存実体、適用範囲、未認定理由を返す |
| 合成の検査 | 追加側の全依存先の定義・包含を検査。二重所有・二重定義は入力不正。追加一般包含・定義欠落・定義循環は未認定 |
| 正の推論 | S1 は N→各連言要素と連言→N、S2 と一般包含は一方向の規則に展開。有限の事実と証明の固定点を計算する |
| 文脈と採用 | 各 view・context を分離。人の確認・参照時点・明示訂正を経た肯定主張だけを規則の前提にする |
| 根拠 | 元の assertion、review、定義・包含への参照を返す。定義根拠はパッケージのハッシュと入力内 pointer まで追跡できる |
| 衝突と未知能力 | 導出された肯定と明示的否定の衝突でも文脈全体を停止。未知能力がある文脈では推論を開始しない |
| 上限 | 認定のグラフ検査と規則の ground 適用を計数。途中の認定票や、未完成の閉包に基づく回答を返さない |

旧側をまず単独検証するため、追加側の新しい語彙で旧側の未解決参照を埋めることはできません。拡張の参照は旧側と追加側の和で解決するので、初期 P01 のように旧 A/B を extension に再宣言せず参照できます。query のパッケージでは必要な宣言を同梱するか、依存先とそのハッシュを明示します。

認定は旧データを固定した旧語彙の文に対するモデル保存の**十分条件**です。新しい所属データ、採用方針、対応表の変更を保証しません。条件外の not_certified を非保存・危険の証明とせず、保証欄は null にします。根拠は [R5 の S1/S2](05-principles.md)、実行時の意味は [P0 契約](06-p0-contract.md) を参照してください。

## 開発テストと参照計算

Python **3.14.4** で **62 件の unittest が通過**しました。P0-a の 36 件を維持・更新し、26 件を追加しました。以前の「定義推論は未実装」と「check_extension は未実装」という能力境界のテストは、実装後の結果に更新しました。初期三例の入力・期待値は変更していません。Python 3.11 自体での実行は未確認です。

- 保存認定とは別の参照計算として、二個体の有限領域で全解釈を列挙。S1、S2、混合連鎖の三例で、追加後の全モデルを旧語彙へ射影した集合が旧モデル集合と一致しました。一般領域の証明を置き換える検査ではありません。
- 正の推論とは別の参照計算として、三述語の全解釈を真理値で評価。S1、S2 と旧包含、一般包含の三理論について、肯定種データの全 8 通り、計 24 入力で全モデル共通の肯定と回答が一致しました。
- 全ての草案例の生バイト SHA-256・サイズと必須パスを確認し、入力を変更しないことを検査しました。
- 同じ引数・同じ文脈が揃わなければ連言から導出しないこと、包含の方向を逆に使わないこと、新しい個体・所属を作らないことを確認しました。
- 依存先に隠れた一般包含・未定義の新記号、依存ハッシュの不一致、旧依存語彙の再導入、役割不一致、未解決参照を検査しました。
- 否定を規則の前提や対偶へ使わず、未確認・将来の主張で導出しないこと、導出後の衝突に両根拠を残すことを確認しました。
- 循環包含・循環定義が有限の query として停止すること、直接主張の根拠を循環で水増ししないこと、複数導出の根拠選択と再実行が決定的なことを確認しました。
- 0・認定途中・閉包途中・閉包完了直後の予算境界で、未完成の認定や途中回答を返さないことを確認しました。

循環定義を query で計算できることと、保存の十分条件を認定できることは別です。証明は事実ごとに短い導出を優先して一つ選び、全ての代替証明は列挙しません。根拠の具体的な選択規則、入力内参照、ステップの計数は契約に追記しました。
