## 実装と検証の範囲

採用・保留・訂正・未知能力の停止は P0-a に、正の閉包は P0-b に先行実装済みです。今回はそれらを組み合わせた具体例と開発テストを追加し、次の出力を具体化しました。既存の選択方針や保存認定の条件は変更していません。

| 状況 | 出力・判断 |
| --- | --- |
| 可視主張に未知の必要能力 | `missing_capabilities` に加え `blocking_assertion_refs` を返し、どの主張の意味が解釈できず停止したかを示す |
| 肯定閉包と明示否定の衝突 | `conflicts` に ground atom と `positive_evidence`・`negative_evidence` を分けて返す。従来の集約 evidence も維持 |
| 未確認 AI 候補・疑い | 保留して原情報を残す。別の人の確認後も生成元の情報は書き換えない |
| 記録・確認・訂正の時間差 | view ごとに採用と閉包を再計算。将来の確認を先取りせず、確認前の訂正では旧主張を外さない |
| 家族・時点・用途・参照の違い | 別文脈の事実を暗黙に結合しない |
| 方法の新たな必須化 | 既存の記録から得られれば出典付きの回答、なければ `needs_information`。存在しない方法値を作らない |
| 否定の限界 | negative N は N の ground query の opposed を支えるが、定義から対偶を計算して negative A を作らない |

未知能力による停止は、保留・訂正済みを含む**全ての可視主張**を対象にする既存契約です。未知修飾が訂正の意味まで変えるか判断できないため、訂正済みの記録でも必要能力を無視しません。未来の主張はその view を止めず、別文脈の回答も止めません。この制約を [P0 契約](06-p0-contract.md) に明記しました。

## 開発テストと再現性

Python **3.14.4** で **85 件の unittest が通過**しました。P0-b の 62 件を維持し、23 件を追加しました。Python 3.11 自体での実行は未確認です。

- 生成元 4 種、certainty 2 種、符号 2 種、確認の欠落・直前・一致・未来の 4 条件、計 64 入力を期待表で照合しました。生成元を理由に確認条件を緩めません。この 64 入力は一つの単体テスト内の条件数であり、85 件に加算しません。
- 確認前の訂正が旧主張を消さず、後から旧主張が確認されても訂正済みを復活させないことを検証しました。分岐する訂正は明示的な解消が揃うまで衝突のままで、多数決・最新優先にはしません。
- 別文脈を指す訂正を拒否し、文脈の対象者・対象時点・用途の違いを越えて連言を作らないことを検証しました。同じメタデータでも別参照を暗黙の同一文脈とはしません。
- 直接・導出の衝突を atom ごとに分け、複数衝突・複数支持でも符号別の根拠を保持しました。未知能力の停止元も全ての該当可視主張から集計します。
- 未知能力が必要な保留・訂正済みの主張、未来の主張、既知能力、依存先の未対応 profile を区別しました。
- 必須問い合わせの supported・opposed・undetermined・conflict・unassessed を確認し、状態に応じた情報要求を検査しました。変数付き否定や結合の否定を、単一 ground atom の否定検索で代用しません。

P22 の二入力を同じ実装・profile・上限で照合しました。同じ入力の二回実行は全項目一致。別順序の入力は正規化入力ハッシュが異なり、**そのハッシュを除いた結果全体が一致**しました。CLI の再実行でも確認し、原入力も変更していません。予算 0・1・4 の打切り結果も入力順に依存しないことをテストしました。

並べ替えたのは contexts/views/queries/assertions/reviews と結合 atoms です。役割・引数の順とパッケージ実体は固定しました。パッケージの定義配列の順を変えると、ハッシュと根拠 pointer が変わるため同じ実体とは扱いません。今回の再現性を、異なる意味プロファイルや実装間の互換性としません。
