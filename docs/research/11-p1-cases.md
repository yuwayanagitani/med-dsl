# P1：H01〜H20 の受入条件草案

作成日：2026-10-18。状態：**作成者草案・未実行**。P1 の実装結果・独立確認済み正解ではありません。[研究対象](11-p1-design.md) と [意味・引き継ぎ契約](11-p1-contract.md) を評価の前提とします。8件の [JSON 設計例](../../examples/p1/README.md) は具体的な入力と期待条件を持ちますが、実行 request の schema は後続で定めます。

## 意味能力の追加

| ID | 入力・問い | 必須の期待条件 |
| --- | --- | --- |
| H01 | 世界 wx/wn の重み7/10・3/10、X={wx}。採用済み予測報告から X の確率を読む | computed、型は forecast_probability、値7/10。対象・区間・モデル・予測参照と報告の確認根拠を返す。臨床 X の支持は追加しない |
| H02 | H01 の重みを1/1・0/1にする。別に、同じモデルで AI の未確認報告だけを与える | 確認済みでも回答は予測値1/1で、発生の断定に変わらない。未確認報告は保留して値回答を undetermined/null とし、元 artifact と生成由来を保持 |
| H03 | 同じ標本空間で、w11/w10/w01/w00 の重み3/10・3/10・3/10・1/10。A={w11,w10}、B={w11,w01} | Pr(A)=Pr(B)=3/5、Pr(A∧B)=3/10。独立と仮定した9/25を返さない。別モデル・別期間との連言は受け付けない |
| H04 | 分母0、重複世界、未宣言世界を指す事象、または総和9/10の予測 | 入力不正。丸め・正規化・不足世界の補完をしない。計算結果を0や1にして成功にしない |
| H05 | 同じ artifact を二主張が異なる時点で報告し、確認・訂正の時点も異なる | 同じ view・方針で採用された報告だけを使う。artifact の存在だけで採用せず、生成元・原主張・確認を追跡する。異なるモデルの報告を平均しない |
| H06 | profile/仕様 hash/対応演算の不一致、未知の否定修飾、自己申告 read_only | 仕様実体の不一致は invalid_input、未対応 profile は unsupported_profile、文脈内の未知能力は unassessed。既知 native handler の検査なしに無影響と認定しない |

H01〜H06 の予測は、どの値でも臨床上の真偽と別の型です。人の確認は報告を確認した根拠であり、モデルの校正・臨床精度の正解ラベルではありません。

## コアの意味構造の改訂

| ID | 入力・問い | 必須の期待条件 |
| --- | --- | --- |
| H07 | P0 の二観察 O(e1,s1,m1,陽性)、O(e2,s2,m2,陰性) を、同じ内部事象の四役割へ移す | s1/m1 の結果は陽性、s2/m1 は未決。返すのは元の query の変数だけで内部 z を漏らさず、両原主張の由来と履歴を読み戻せる |
| H08 | 同じ key k0 を持つ二つの異なる四つ組、または同じ四つ組を支える異なる二主張 | key だけで内部事象を統合せず、原台帳・assertion ごとの新鮮な ID を使う。旧回答は集合で重複除去し、複数の原根拠を保持。旧側にない key 一意性を加えない |
| H09 | H07 の後で、生成した z の件数・同一性を旧 Q の保証に含めたいと指定 | 旧 O の問い合わせ範囲には含めず、その式は引き継ぎ対象外と返す。新しい問い合わせ能力と、旧回答の保存を区別する |
| H10 | 検体・方法・結果が、それぞれ別の z から取れる誤った翻訳 | 旧ではない s2/m1/陽性が真になる反例を示し、not_certified。役割ごとの存在を、同じ事象の存在としない |
| H11 | 活動事象から方法だけを削除する、二つの方法を与える、内部 ID を他の原主張と衝突させる | 入力不正。欠落を既定の方法で埋めず、恣意的な一つの役割値を選ばない |
| H12 | 旧主張の negative、疑い、未確認、明示訂正、本人/家族/時点/用途の別を含む履歴 | 採用・保留・訂正済みの読み戻しが旧方針と可換。negative O は四つ組全体の否定で、negative role に分けない。衝突は両根拠で停止し、原履歴を消さない |

H07 の「陰性」は観察値の一つであり、主張 polarity=negative とは別です。後者を検査するのは H12 です。C1 の論理的なモデル構成と、実行する有限の結合問い合わせの分母も別にします。

## 保存の条件・合成・再現

| ID | 入力・問い | 必須の期待条件 |
| --- | --- | --- |
| H13 | 旧 T0=∅、D={A(a)}。新 T1={A⊑B}、同じD、E/rは同じ記号の対応 | 各新モデル内の式の対応だけでは認定しない。旧 A={u},B=∅ を持ち上げられず、旧では非含意の B(a) が新では含意。not_certified と反例 |
| H14 | 旧 A(x)→∃y(r(x,y)∧B(y))、D={A(a)}。新側ではこの存在制約を除去する | 旧では∃x B(x)を含意するがB(a)は非含意。新側では存在も非含意。名前付き原子の一致だけで保存とせず、aを存在証人にしない。一般の存在推論は参考意味で、P1の初期実行対象外 |
| H15 | 旧側で未記載の X(a) を、新コアでは偽とする。Qには¬X(a)を含む | 新しい否定の意味による差を報告し、旧意味の保存は未認定。P0の支持上も undetermined→opposed を黙って同じ回答としない |
| H16 | 四項関係→役割事象→内部参照の一対一改名。全ての型・依存・方針・中間実体が一致 | E/rと原根拠の対応を二段階で合成し、旧Qの公開bindingを保持。内部変数を新鮮にし、単独票だけでなく全体の対象Qと入力hashを照合する |
| H17 | 四つ組→値集合への射影→値集合の無損失符号化 | 二段目だけの保存認定を全体へ流用しない。同じ値集合へ写る二旧記録で異なる旧Qを示す。原記録の別添えなしでは全体の旧Qを保証しない |
| H18 | 旧理論は制約なし、新理論は台集合が高々2要素。1/2要素だけの全モデル検査は一致 | 3要素の旧モデルを持ち上げられない。有限検査の一致だけでは全モデルについて certified にしない。これはFOL参考意味の反例で、P0 queryではない |
| H19 | 原バイト列と参照は残るが、旧処理系または依存実体を取得できない | legacy_replay の可用性を失ったことを明記。新意味への引き継ぎの証拠とは別に記録し、原保存だけで解釈可能としない。新側の保証も別途確認なしに成功・失敗へまとめない |
| H20 | 計算予算0、有理数/中間結合の上限超過、または追加モジュールの処理で共有予算が尽きる | resource_limit と未評価範囲。途中の確率・binding・認定票を完全回答にしない。計算が完了しないことを意味の喪失・0確率・否定へ変えない |

H13/H14/H18 の「含意・非含意」は参考モデル理論の判断です。P0/P1 の実行状態 undetermined と同一の列へ集計しません。

## 初期の確認方法

- 予測の参照計算は、列挙された世界の整数比の和と集合の交差を直接計算する。独立性の仮定を使わない別計算を基準にする。
- 事象化は、四つ組集合を直接検索する参照計算と、同一 z での結合・公開変数への射影を比較する。値集合への平坦化を負例にする。
- 真理条件・モデル被覆のテンプレートの導出は手作業の条件を再確認する。小領域での全列挙は実装の検査に使えても、一般の認定の代替にしない。
- 主張の採用は、同じ対象・時点・方針の期待表と読み戻しで確認する。P0 の37例を別枠で回帰する。

最小条件は、全20件の実行用入力・期待値が揃い、指定条件からの逸脱、無根拠な臨床肯定、誤認定、停止の見落としが0であることです。正の予測値・保存される結合を必須にし、全棄権を通しません。独立確認・正解凍結・実行コミットとhashの固定を、作成者草案の設計・実行と別に記録します。現時点のP1合格数は未評価です。
