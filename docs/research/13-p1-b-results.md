## 実装した範囲

`p1-events-draft-1` の native handler と固定仕様を追加し、事象化・読み戻し・新側の問い合わせ・引き継ぎ比較の4操作を実装しました。P0 と P1-a の形式・意味・固定仕様は保持しています。

選んだ四項関係の各原主張に、原台帳・assertion の組から新しい事象IDを作ります。同じ key の観察も同じ四つ組の複数報告も別事象として保持します。四つの役割、原由来、疑い・未確認・否定・確認・明示訂正を保持し、`restore_events` で source snapshot 全体を復元できます。欠落や複数の方法を選び直したり、既存名と衝突する事象IDを受け入れたりしません。

新側は採用済み事象から Active と四役割の表を作り、同じ内部変数を使って実際に結合します。旧処理系の回答を新側の回答として流用しません。内部変数はユーザーの変数と衝突しないように発行し、元の変数だけへ射影します。重複回答は集合にし、複数の原主張・確認根拠は統合します。他の述語と単項定義規則も保持します。

原側の再実行は legacy_replay、新側の評価は native_event_roles と明記します。同じ view・採用方針での原履歴、採用 metadata、状態・binding・assertion/review/definition 根拠を照合します。否定は四つ組全体へ適用し、一つの方法の否定へ分解しません。未知能力・衝突は比較不能で、差分は null です。

## 計算上限と実行保証

基本例の生成・読み戻しは各6 steps、新側の二問は34 steps、原・新・比較の共有予算では41 stepsです。各途中停止点を検査し、未完成 artifact や一問の途中の binding を返さないことを確認しました。共有予算40では一問の比較だけが完了し、残りの差分と certificate は null です。

構文上限内でも計算完了は保証しません。同じ四つ組を65主張が支え、二つの原子式を結合する例では、原側が完了しても新側の中間 binding が4096を超えます。resource_limit として停止し、回答の喪失や正常な空差分とはしません。公開 binding の1000件超過も、最初の1000件を完全回答として返さず停止します。64 atom から320 atomへ展開する構文境界は、一事象の入力で別に検査しました。
