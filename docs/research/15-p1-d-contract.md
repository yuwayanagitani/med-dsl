# P1-d：共通台帳・作成者草案の固定・総合評価契約

作成日：2026-10-19。契約 `p1-integrated-snapshot-draft-1`。P1-a/b/c の実行意味や期待結果を変更せず、[H01〜H20](11-p1-cases.md) の工学的照合をまとめます。独立確認後の評価用正解の凍結とは別です。independent_review/evaluation_frozen は false を維持します。

## 固定する実体

[共通 manifest](../../examples/p1-evaluation/manifest.json) は、各相対パスの生バイト SHA-256 とバイト数、その一覧の canonical JSON digest を持ちます。対象は runtime の Python・native仕様JSON、全テスト、全評価スクリプト、P0/P1の意味契約・初期20条件・各実行契約・本契約、既存 P0/P1-a/b/c の全JSON・manifest、元の P1設計JSON・manifest です。単一プロファイルへ統合せず、各 native仕様と原manifest の照合も維持します。

台帳自体は自身のハッシュ対象から除き、実行記録がその生バイトハッシュを持ちます。結果文書・進捗用READMEは束に含めません。実行時の git HEAD・作業差分、Python版を記録し、コミット前の検証は後で対象コミットの実体と照合して区別します。Gitコミットの時刻やバージョン名だけで実行実体の一致を推定しません。

通常評価は再固定しません。実体や一覧の変更時は計算前に終了コード2で停止します。再固定は変更理由と差分を確認したうえで `--create-snapshot` によって明示し、その操作自体は評価を行いません。元の期待値・manifest を更新する場合は、旧結果を残し変更理由と版を別途記録する必要があります。今回その変更はありません。

## 評価手順と分母

全実体・閉じたファイル一覧・phaseごとのprofile/仕様hash・全case ID・期待条件の構造・設計時の依存実体を確認してから計算します。一つでも不一致なら途中の評価記録を発行しません。必須パスは空でない文字列/非負整数の配列で、重複を認めません。欠落したパスは null との一致にせず、真偽値と整数を含め JSON の型を区別します。

| 台帳 | 条件 | JSON | 必須パス |
| --- | --- | --- | --- |
| P1-a | H01〜H06・H20：7 | 31 | 141 |
| P1-b | H07〜H12：6 | 22 | 150 |
| P1-c | H13〜H19：7 | 27 | 126 |
| P1 合計 | 20 | 80 | 417 |
| P0 回帰（別枠） | P01〜P22：22 | 37 | 221 |

各入力を複製して API を二回実行し、入力保持と型を含む結果の一致を確認します。`--cli` 時は CLI も各二回、JSON全体と終了コードを照合します。P0 の P22 は、異なる入力hashと、それ以外の結果の一致も確認します。expected は推論に渡しません。全条件の必須パスと再現確認が通れば終了コード0、不一致は1、評価用入力不正・実体変更・実行エラーは2です。予期した invalid_input/resource_limit 等を返す負例も、期待通りなら例として合格です。

終了時にも束を再確認し、ディスク変更を検知した実行は記録を発行しません。全件完了した照合記録だけを `data/research/p1-d/` 以下の指定先へ一時ファイルから置換して保存します。不一致を含む完了記録は passed=false。中断・例外は成功記録にせず、前回の記録があればその日時・HEADのまま残します。これは同時編集を許容する仕組みではありません。評価中は対象ファイルを編集しません。

## 台帳の意味と証拠の強さ

| 条件 | 意味層 | 確認する証拠と境界 |
| --- | --- | --- |
| H01〜H06 | 型付き有限予測 | 有理数・同一標本空間・確認根拠・能力停止。臨床の真偽や校正を保証しない |
| H07〜H12 | 有限の事象・支持・履歴 | 同じ事象の役割結合と旧変数への射影、原履歴、反例。有限照合票を全モデル認定にしない |
| H13/H14/H18 | 一階論理の参考意味 | 検査済み反例と限定した含意導出。恒等な文集合以外の一般的保存判定器はない。P0の未決と非含意を同一に集計しない |
| H15 | 欠落を否定に変える方針変更 | 未決と否定の差、閉世界の仮定。方針変更を保存として認定しない |
| H16 | 既知の事象化・単射改名 | 実体・依存・方針・翻訳後Q・履歴を検査した十分条件。認定は原履歴と両計算が完了した旧支持断片。計算完了・任意の新Q・新データは保証外 |
| H17 | 射影の対象範囲 | 喪失の衝突例、保持列のQ、符号化した中間値の一致、別添えの実利用を区別。後段の認定を全体へ流用しない |
| H19 | 可用性と独立した引き継ぎ | 提供inventory/native registryだけの点検。旧バイナリの実行はしない。保存・解釈・再実行可否・新側保証を区別 |
| H20 | 資源上限 | 台帳ではP1-aの予算/有理数負例。P1-b/cの中間結合・合成予算等は固定した開発テストで補足。全上限の全組合せを列挙したという主張はしない |

本評価の20/20は、この作成者草案の指定条件との一致です。誤認定や根拠のない肯定が0という主張も、検査した必須パス・開発テストの範囲に限ります。全棄権を通さない正例も含みますが、未知体系・医学的正解・未来の全変化・無限更新の極限に対する保証は導きません。
