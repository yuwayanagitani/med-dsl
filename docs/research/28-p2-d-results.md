### X11 の範囲

- **有限の旧入力**：旧入力は P0・P1 の 117 件。再固定は pin 3 つの機械的な置換。「旧入力が黙って再解釈されない」は、この 117 件について確かめたことで、一般の版で成り立つことの証明ではない。
- **旧入力が行使しない変更は見えない**：宣言した変更のうち、確認の時刻順（V-3、RV-05）、不認定の理由コード（V-4・V-5、RV-02）は、旧入力に該当する例がなく、旧入力の比較では観測されない。別の根拠（`examples/review/…`、`tests/review/test_draft2_changes.py`）を挙げるにとどまる。
- **宣言は作成者の主張**：宣言にない差は検出するが、宣言が実際の変更を過少に申告していても、旧入力に現れない限り検出できない。

## 3. 検査で分かったこと

1. **予算の掃引が、P0 の 35 要求で空振りだった。** 初版の `budget_violations` は掃引の範囲を `steps_used` から決めていたが、P0 の結果は `steps_used` を持たないので、予算 0〜2 しか掃引していなかった。範囲を、予算を倍々にして求めた完了する予算の上限から決めるように直し、評価の回数は 2,671 から 2,936 になった。広げた掃引でも違反は 0 だった（実装の欠陥は見つからず、検査が浅かった）。さらに検査器のテストで、P0 の要求が予算 0〜2 では完了しないこと（空振りでないこと）と、掃引の回数が 10 回を超え 40 回未満であることを確かめている。
2. **forecast の宣言の文言が、仕様と食い違っていた。** 宣言の `stops.invalid_input` は「予算に依らず入力不正」と書いていたが、重みの総和が 1 かの確認は重みの加算を課金しながら行うので、予算が足りないと入力不正と判定する前に `step_limit` で止まる（`forecast_spec.json` の steps に「正規化の比較」が含まれる）。検査が一般の不変条件として「入力不正は予算に依らない」を課して初めて見つかった。挙動は仕様どおりなので、宣言の文言を直した（`p1-finite-forecast` の `stops.invalid_input`）。この一件だけを根拠つきの許容として載せ、ほかの入力不正には広げないことをテストが確かめる。
3. **道具が Git 管理外にあった。** 変異表・実行器・生成器は `data/research/` にあり、確認者が変異検査の主張（P2-a〜P2-c の 53／35／39／28 件）を再現できなかった。リポジトリに移し、実行器の既定を一時ディレクトリ・このリポジトリに変え、変異表の置換元が実装の変更で古くならないこと、生成器が固定した例・宣言をバイト単位で再現すること、固定済みの出力が基準と一致することを、テストで検査する。生成器は、設計文書（`docs/research/`）を複製に含めないと失敗する（P0 の契約の hash を参照するため）。
4. **検査器自体の変異検査で見つかったもの。** 最初の 56 変異のうち 3 件が見逃された。(a) **B13**：P0 の要求で、完了する予算の探索を無効にしても（掃引が上限の 300 まで伸びても）どの検査も失敗しなかった。掃引が完了の少し先で止まること（10 回を超え 40 回未満）を確かめるテストを足した。(b) **B17**：完了済みの行の状態（`unassessed`・`blocked`）を比較から除いていた条件は、全 203 要求で外しても違反が 0 で、使われていない除外だった。除外を削除して検査を厳しくした（この変異も削除）。(c) **C04**：固定した hash の変更による拒否の条件のうち、状態が `invalid_input` であることの確認を外しても検出されなかった。別の状態が同じ理由コードを持つ入力は変更として扱うテストを足した。

## 4. 検査器の変異検査

共通部品 [p2_checks.py](../../scripts/research/p2_checks.py)、版の比較、統合評価の判定を一つずつ壊した変異を、対応するテストモジュールで検査した（[mutrun_checkers.py](../../scripts/research/p2/mutrun_checkers.py)）。変異後の木では固定対象の台帳を作り直す（検査器のファイルは固定対象なので、作り直さないと台帳の不一致だけで失敗し、検出の判定にならない）。対照（変異なし）は失敗 0。

| 対象（変異の ID） | 変異 | 検出 |
| --- | ---: | ---: |
| 予算の不変条件（B01〜B16）：判定の分岐、許容の例外、掃引の範囲、値を持つ項目の一覧 | 16 | 16 |
| 版の分類と正規化（C01〜C10） | 10 | 10 |
| 記録との照合（R01〜R08） | 8 | 8 |
| 版の再構成の配線（V01〜V05）：再固定、pin の読み取り、宣言した付加の扱い | 5 | 5 |
| 比較器の終了コード（V06〜V07） | 2 | 2 |
| 統合評価（E01〜E14）：分母の照合、lock の再確認、出力先、終了コード、凍結の主張 | 14 | 14 |
| **計** | **55** | **55** |

最初の表は 56 件で、3 件が見逃された（後述の検査の穴）。穴を直してから、全 55 件を最終版の検査器で実行し直した（対照は失敗 0）。

変異は作成者が選んだ集合です。検出されたことは、その種類の退行を検出できることを示すだけで、他の退行がないことは示しません。

## 7. 限界と次

- 独立確認は未実施で、確認者もいません。[27 の §5](27-p2-d-design.md) の PO13〜PO18 と内部判断 12 件は、独立の確認で覆り得ます。`independent_review` と `evaluation_frozen` は false のままです（評価の「固定」は分母と実体の hash の固定で、凍結ではありません）。
- X12 の不変条件は、型によらない最小の条件です。各拡張の意味の正しさ（候補集合が正しいか、など）は、各拡張の義務と手作業の導出に残ります。
- X11 は有限の旧入力での実演で、版の手順が将来の版・別の拡張でも成り立つことの証明ではありません。
- 次の候補は、(1) 独立の確認者を得て G0 から PO13〜PO18 を確認すること、(2) P2 の次のパイロット（候補 B 有効期間つきの主張、C 単位つきの数量）を選ぶことです。どちらも実施前に利用者の確認を取ります。
