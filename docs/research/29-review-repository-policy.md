# 独立確認の運用方針：現在のリポジトリと英語の別リポジトリ

決定日：2026-10-20。決定者：利用者。状態：**現在の開発・研究の進め方として適用**。

## 利用者の指定

> 今回のこのリポは確認者なしで行きます。確認者を入れる場合は、別のリポ（そちらは英語で記述）を立ててそちらで確認が必要な時点から進めます。

この決定は、[P2-dの完了時点](28-p2-d-results.md) で挙げた「独立の確認者を得てG0から進める」という次の候補の運用を更新します。現在のリポジトリで確認者を確保することは、今後の研究・実装・内部検証の進行条件にしません。

## 現在のリポジトリ

- 日本語を基本に、作成者側の研究・実装・内部検証として進めます。独立の確認者は置きません。
- 独立確認の代わりに、内部の検証を独立確認済みと表示することはしません。`independent_review` と、独立確認済み正解の凍結を表す `evaluation_frozen` は false のまま扱います。草案の実体・分母をhashで固定することとは区別します。
- 証明義務、内部判断、反例、未対応、検査の欠落、仕様・実装・期待結果の変更理由、旧版と実行根拠を引き続き残します。独立確認を行わないことによって、検証済みと主張できる範囲は広がりません。
- この決定は研究成果の独立確認に関するものです。原主張の人による確認、AI生成候補の保留、未知能力・不明情報への停止といった、モデル上の条件は維持します。

## 将来、確認者を入れる場合

英語で記述する別リポジトリを立ち上げ、そのリポジトリで独立確認を進めます。最新の実装から始めるとあらかじめ決めず、対象の主張や判断について**確認が必要となった時点**に戻って再開します。

1. 対象となる時点を、元リポジトリのコミット、契約・仕様の版、manifest・実体束のhashで特定します。必要なら複数の版を引き継ぎます。
2. 対象の意味定義、証明義務、入力・期待結果、内部判断とその理由、反例、未解決点、再現コマンド・環境・実行根拠を英語で記述します。元の実体を参照できる形で保持し、翻訳や再実装による変更も区別します。
3. 別リポジトリでG0（資料固定）から、担当・独立性・対象と保証範囲を記録します。そのうえで、必要な証明義務と内部判断を確認し直します。英語化や別リポジトリへの移行だけで独立性が成立したとは扱いません。
4. 不一致の裁定、修正、再実行、独立確認済みの期待結果の凍結は、別リポジトリで記録します。現在の内部判定をそのまま承認済みとして引き継ぎません。

以前に整えた [レビュー計画](16-review-plan.md)、[P0/P1の再開点](17-internal-run-ai-001.md)、[P2のPO13〜PO18・内部判断J01〜J12・再開手順](27-p2-d-design.md) は、その際の準備資料として保持します。確認者を現在のリポジトリに割り当てる手順としては適用しません。
