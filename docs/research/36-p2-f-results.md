## 1. 実装範囲と契約

| 実体 | 内容 |
| --- | --- |
| [quantity.py](../../src/med_dsl/quantity.py) | 有理数・点・有限非空区間の検証、正の倍率による換算、可能な大小関係の集合、未知・比較不能・資源停止 |
| [native仕様](../../src/med_dsl/quantity_spec.json) | 5量種・7単位の架空の閉じた表、出力領域の形、エラー名、課金と整数上限 |
| [host.py](../../src/med_dsl/host.py) | 新schemaを専用経路へ登録。旧基底の5ファイルは変更しない |
| [R2宣言](../../extensions/p2-quantity-literal.json) | 共通4＋R2の5＋QT-1〜8の17義務、24防護例の参照 |
| [実行例](../../examples/p2-quantity/README.md) | 手指定のQ24/N12/B4を79 JSON・609必須パスと補助テストへ展開 |
| [参照計算](../../tests/p2/quantity_oracle.py) | native表・関数を使わない整数対演算と区間内の証人点の比較 |
| [検査](../../tests/p2/test_quantity.py) | API/CLI、参照計算、予算、型、出自・原情報、非干渉、意味変異の14テスト |

入力は明示した有理数に限り、結果は既約形、原入力は未約分も含めて保持します。区間の比較は代表値に置き換えず、別参照なら区間から独立に選べる二つの値の関係集合、同一参照なら一つの値の自己比較として扱います。これは確率論上の独立性の仮定ではありません。

検査順は、構造・参照・入力次元の矛盾を予算前に検証した後、各行で未知能力、未知量種・単位、次元不一致、量種不一致、計算の順です。未知の単位をもつ自己比較も停止します。未参照の未知リテラルは保存しますが、別の量を読む行を停止させません。

完成した計算だけが `converted_domain` または `relation_set` と、仕様hash・量参照・種類・単位・倍率・出自を含む `calculation_evidence` を持ちます。比較不能・未知・未完了の行では、これらと `certain_relation` はnullです。計算できても `clinical_confirmation: not_evaluated`、`uncertainty_propagated: false`、`converted_to_base: false`、`clinical_assertions_added: []` を維持し、認定を返しません。

R2の枠内に収まり、新しい契約クラスは追加しませんでした。ただし**R2-3は基底の状態を全く読まないため空虚に満たす**という限定があります。これを、確認済みの臨床測定から安全に計算できたという証拠にはしません。単位・量種はprofileと仕様hashの内部名で、共有述語として登録していません。QT-1〜8は量固有の個別義務であり、一般的な義務の自動生成ではありません。

## 2. 手指定期待と意味計算

| 系列 | 分母 | 内容 |
| --- | --- | --- |
| Q | 24条件・24 JSON・318必須パス | 厳密換算、負数、未約分、区間境界、別参照/同一参照、無次元、種類/次元、未知、AI由来 |
| N | 12条件のうち11条件・43 JSON・97必須パス | 入力不正、静的上限、未対応、消費側仕様。N12は下記の回帰・順序・変異で確認 |
| B | 4条件・12 JSON・194必須パス | 予算0、換算8、比較12、同一参照11、二換算14、途中停止 |
| 区間比較の有限列挙 | 3,660行 | 端点{-1,0,1}の15非空区間×4倍率から60領域。別参照3,600組＋同一参照60組 |
| 厳密換算 | 357行と入力範囲内の往復 | 各適合単位対、15区間・負の分数・63bit境界。4単位・2単位・1単位の群で17×(16＋4＋1) |
| seed付き区間 | 500要求・1,000行 | seed `20261020`、有理端点・開閉・正の倍率。比較と換算の二行を照合 |
| 選定した意味変異 | 9件 | 換算方向、浮動小数点化、代表値化、境界、同一参照、量種の無視、未知の自己比較、臨床昇格、課金不足 |

参照計算との照合は合計 **5,017行**で、往復の追加照合はこの件数へ加えていません。比較の参照計算は全端点と隣接端点間の二つの三等分点を証人に選び、整数の交差積で順序を求めます。一つの中点だけでは同じ開区間の大小を見落とすため、二点を使います。実装の端点の存在条件式は呼びません。共有するのは設計された意味と標準整数演算であり、独立の確認者による正解ではありません。

期待は文書35と設計式から手指定し、runtimeの結果で更新していません。N06の小数・NaN/Infinityは正規JSONのfixtureへ入れず、生JSONとAPIのテストに分けます。D01/D02の丸め・字句精度は机上の射影反例として残し、実装済みの射影に数えません。9変異は元ファイルを書き換えず別の関数束として実行し、対応する手指定期待の不一致で検出します。浮動小数点化の防護には `2**53 + 1` を使います。検出範囲は選定した変異だけです。

不正な予算欄を0へ置き換えると入力そのものが修復されるため、その拒否を修復後にも要求していた既存テストの前提を修正しました。元の不正予算の拒否はfixtureとAPI/CLIで照合し、共通の掃引では有効な予算へ置換した要求を評価します。これは予算に応じて入力不正が変わる例外の追加ではなく、従来の例外1件は維持しています。

予算は `1＋数量件数＋6×換算件数＋9×比較件数`。点・同一参照・未知・比較不能でも同じ行料金を先払いし、支払い完了前に計算値を作りません。数量専用の予算掃引は **79要求・652評価、違反0**。共有検査器にも四つの新しい値欄を追加し、それぞれの早期漏出を入れた変異を検出します。

63bit入力と固定表の7bit以下の倍率から、正規化70bit、変換77bit、比較交差積140bit以下という設計上限を検査します。256bitの中間上限はこの固定断片では通常到達しません。防護分岐の単体検査と資源停止の注入は行いますが、自然入力でその上限に達したとは扱いません。

次は、**数量と臨床主張の接続契約の意味設計**を優先します。今回のR2は値の型を扱えますが、その値が誰の何を・どの検体/方法/時点で測ったか、どの確認で利用可能かを扱いません。数量参照を訂正しても過去の計算が新版の値に黙って置き換わらない同一性と、AI候補・未確認情報を臨床判断へ昇格させない採用条件を、まず反例と手指定期待で定めます。

表示の丸め・外部単位構文・実体系への射影は、その接続と分けて扱います。時間や概念分割の個別試験の成功から、接続後の保存を自動的に導きません。R4の実資料評価、共有単位登録表、一般の測定不確かさ、臨床ライブラリ・標準化、未来全体への対応の証明は引き続き未完了です。
