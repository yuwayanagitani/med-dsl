## 3. 共通契約の対応表

### 3.1 七つの欄

各拡張は、旧い意味へ何かを足す「接続」です。次の七欄を、**実際に各設計が個別に決めていた事項**から取り出しました。事前に仮定した枠ではなく、設計文書と宣言の記述を後から揃えたものです。

| 欄 | その拡張が決めていること |
| --- | --- |
| 前提 | 旧い意味に何を足し、何を足さないか。入力側が明示する前提と、方針の差 |
| 版 | どの profile・native 仕様・依存の版に相対か。固定する hash |
| 確認対象 | 人の確認が何を拘束するか |
| 情報の選択 | どの記録を、どの時点で、どの訂正・競合規則で使うか |
| 問い | 答えられる問い、回答型、範囲外 |
| 保持・喪失・追加 | 何が残り、何を分離または失い、何が新しく加わるか |
| 資源・停止 | 課金、予約、未完了の扱い、停止の順序、認定の範囲 |

### 3.2 前提と版

| 拡張 | 前提（足すもの・足さないもの） | 固定する版・依存 |
| --- | --- | --- |
| P2-b 分割 | 公理 A1 包含・A2 被覆・A3 排他を仕様に固定。規則のない単項述語の一文脈・一個体。旧い記録は P1/P2 の区別を持たない | 仕様 hash。基底（採用選択）に依存 |
| P2-c 併用 | 複数の分割（4件・記号10まで）が記号を共有し得る。個別の認定を併用の根拠にしない | 仕様 hash。P2-b の `check_split` を再利用 |
| P2-e 期間 | 入力者が区間全体について主張する（`explicit_interval_uniformity`）。期間を限った訂正（`scoped_revision`）は旧い全体訂正と別方針。UTC 秒精度の有限半開区間 | 方針 `confirmed-scoped-revision`。旧い P0 台帳は取り込まない |
| P2-f 量 | 架空の固定7単位・5量種。正の倍率・有理数・有限非空区間。不確かさは `not_evaluated` | 局所名は profile と仕様 hash に閉じる。述語に偽装しない |
| P2-g 測定 | 三つの架空 property。瞬間の文脈。slot 単位の全体訂正。比較は `matched_context` だけ | P2-f の仕様 hash を固定 |
| P2-h 表示 | 閉じた単一点だけを最近接偶数丸め（0〜6桁）。保存するのは artifact に因子化する問いだけ | P2-g・P2-f の仕様 hash を固定 |
| P2-i 期間つき数量 | 区間の各時点で数量領域が適用されると入力者が明示。包含する部分訂正。持続を推論しない | P2-f の仕様 hash を固定 |
| P2-j 期間つき表示 | P2-i の全計画を固定版で再検証・再実行。単一点だけを丸める | P2-i・P2-f の仕様 hash を固定 |

### 3.3 確認対象と情報の選択

| 拡張 | 確認対象 | 情報の選択 |
| --- | --- | --- |
| P2-b 分割 | 基底の確認（主張への参照） | 基底の採用選択で採用された原子 |
| P2-c 併用 | 同上 | 同上。併用全体の公理の下で全数に判定 |
| P2-e 期間 | 主張**全体**（期間・訂正を含む）への人の確認。確認時刻は主張以後 | 二つの時点を分ける：参照時点 k（記録・確認の可視性）と対象時点 t。除去集合は、t を覆う適格な**全ての**訂正辺から作る |
| P2-f 量 | なし（未確認の量リテラルも計算する。確認済みの印を後付けしない） | なし（入力の数量 ID だけ） |
| P2-g 測定 | 記録版の**内容全体**（文脈・出自・訂正辺・数量の内容 hash）を指定した人の確認 | slot 単位。適格な全辺で除去。複数候補は等値でも競合。未確認の訂正元は除かない |
| P2-h 表示 | P2-g に委譲（計画を再実行する） | P2-g の選択をそのまま使い、結果 JSON は受け取らない |
| P2-i 期間つき数量 | 期間・文脈・数量・依存版を含む内容指定の確認 | 二時点。t を覆う適格な記録、包含する部分訂正、全適格辺から除去、競合は保持 |
| P2-j 期間つき表示 | P2-i に委譲（確認を合成しない） | P2-i の選択を再実行 |

### 3.4 問いと回答

| 拡張 | 操作・回答型 | 答えられる問い | 範囲外 |
| --- | --- | --- | --- |
| P2-b | `query_split`・`candidate_set` | 分割後の部分の候補集合（`asserted`・`single`・`open`・`narrowed`・`no_parent`・`parent_opposed`・`inconsistent`）と情報要求。旧い問いは `base` として不変 | 文脈をまたぐ推論、時間、定義のある述語 |
| P2-c | 判定・併用の問い合わせ | 併用の保存性（認定または反例）、併用での候補集合、個別との差 | 情報を失う段（射影）を含む鎖 |
| P2-e | `probe_temporal_literal`・`temporal_literal_probe` | 時点 t の `positive_only`・`negative_only`・`both`・`neither`。常に `not_certified` | 期間不明の精密化、終点なし、持続の推論 |
| P2-f | `evaluate_quantities`・`quantity_literal_result` | 換算した領域、比較の関係集合 | 不確かさ、丸め、臨床採用 |
| P2-g | `evaluate_measurements`・`measurement_literal_projection` | 選択した記録版に基づく換算・`matched_context` の比較、情報不足・競合・比較不能の診断 | 縦断比較、検体・方法の同等性推論、相関 |
| P2-h | `project_measurement_displays`・`measurement_display_projection` | 表示文字列、セル全体で一定の閾値の問い。`exact_value` は範囲外 | 原値一般、区間の表示 |
| P2-i | `evaluate_temporal_measurements`・`temporal_measurement_projection` | 時点 t で選ばれた記録の換算。常に `not_certified` | 比較、表示、瞬間・集計からの期間の生成 |
| P2-j | `project_temporal_measurement_displays`・`temporal_measurement_display_projection` | 表示文字列、セル一定の閾値。記録・時点・期間・原値の問いは、artifact からは範囲外（別添えがあれば `source_replay` として分離） | 区間の表示、原値・記録の保存の認定 |

### 3.5 保持・喪失・追加

| 拡張 | 保持 | 喪失・分離 | 追加 |
| --- | --- | --- | --- |
| P2-b | 旧い問いの結果、原記録 | P1/P2 の区別は記録にないので確定しない（候補集合）。基底の状態へ変換しない | 公理 A1〜A3、情報要求 |
| P2-c | 個別の結果（併用と併記） | 個別の認定は併用の根拠にならない | 併用全体の公理の下の保存性判定と反例 |
| P2-e | 原記録・確認、旧い全体訂正の経路 | 期間不明は否定にも全期間にも読み替えず停止 | 区間一様性、期間を限った訂正（旧い意味との差は方針差として明示） |
| P2-f | 原入力（負数・未約分）と正規化の分離 | 丸め、不確かさ、外部の字句 | 次元・量種・単位の局所表、区間の関係集合 |
| P2-g | 原記録版・確認・訂正根拠・両出自 | 対象時点が異なる比較は `not_comparable`、医学的同等性は扱わない | 内容を指定した確認、slot 選択、変数の同一性（記録版ごと） |
| P2-h | 原値を上書きしない | 表示が失う区別（例：1.21 と 1.24 が同じ表示） | 表示 artifact の型、丸めセル、因子化の範囲 |
| P2-i | 全記録・確認・訂正根拠・二時点・原順序 | 瞬間・集計から期間への持続は追加しない | 区間一様性、包含する部分訂正、期間を含む内容確認 |
| P2-j | 二時点・選択記録・確認・訂正根拠は応答の根拠に保持（artifact の外） | artifact は原値・記録・時点・期間を持たない | artifact の型（P2-i・P2-f の版を含む）、別添え `source_bundle` と `source_replay` の分離 |

どの拡張も、`converted_to_base=false`、`clinical_assertions_added=[]`、臨床確認と不確かさは未評価、を共通の境界として保ちます。

### 3.6 資源・停止・認定

| 拡張 | 課金と予約 | 打切り・停止 | 認定 |
| --- | --- | --- | --- |
| P2-b | 開始・行・語彙ごとに課金 | 未完了の行は候補を持たない | 認定票を出す操作ではない |
| P2-c | 判定は全数 | 判定は完了するか、認定票を出さない | 併用全体の判定による認定または不認定 |
| P2-e | 開始1＋可視主張＋適格な訂正辺＋行の確定 | 未完了行は値なし、完了行は保持 | 常に `not_certified` |
| P2-f | 1＋数量＋6×換算＋9×比較 | 63bit 入力・256bit 中間の上限。未完了はnull | 保存認定は発行しない |
| P2-g | 行の料金を先払い。子（量）の予算8/8/12を予約 | 子の部分結果は使わず、未完了の値・根拠はnull | 診断のみ（`not_certified`） |
| P2-h | 計画の料金 C を先払い（標準 C=16、一表示一質問で合計28）。子は一度だけ呼ぶ | 最後の1不足でも認定なし | 表示の問いに限り（`display_questions_only`）、全質問が保存のときだけ |
| P2-i | 行の料金（16/27/21/34など）を先払い。子は一度だけ | 未完了の値・完成根拠はnull | 常に `not_certified` |
| P2-j | I の全計画の料金 C を先払い。C が親の上限を超えれば I を呼ばず全行未完了（例：C=125443＞100000） | 子が部分結果を持っても拾わない | artifact だけに因子化する問いに限り |

停止の順序は全拡張で共通です：構造・参照・hash の不正（`invalid_input`）は予算の前に、未対応（`unsupported_profile`）、未知の能力、資源停止の順。予算 0 でも入力不正は予算に依らず同じ結果、という不変条件は、全942要求の掃引で確認しています（[P2-d](28-p2-d-results.md) の枠組みの拡張。許容する例外は仕様が課金を明記した1件のみ）。

## 4. 保証と限界

### 4.1 条件から導ける性質（手作業の導出）

次の性質は、設計文書の導出（TE-L1〜5、QT-L1〜5、MB-L1〜6、DP-L1〜5、TM-L1〜6、TD-L1〜5）から、能力にまたがるものを取り出したものです。**すべて作成者の手作業の導出で、機械検証も独立確認もしていません。** 前提を外すと成り立ちません。

| ID | 性質 | 前提 | 導出元 | 含まないこと・限界 |
| --- | --- | --- | --- | --- |
| G1 | k 以下の記録・確認だけで選択を作れば、妥当な未来の追加は同じ (k, t) の完成した選択を変えない | 同じ方針・依存版で、双方の計算が完了する | TE-L1、MB-L2、TM-L4 | 既に見える主張への確認が k までに追加される場合は範囲外。hash・保持一覧・予算量の一致は含まない |
| G2 | 確認が記録版の内容 hash を拘束すれば、値・期間・訂正辺の変更に旧い確認を流用できない | hash の衝突を別の内容の同一視に使わない | MB-L1、TM-L1 | 記録と確認を一緒に偽造する攻撃、本人認証 |
| G3 | 訂正元が除かれても、除去集合を適格な全辺から作るので、訂正された元の記録は自動復活しない | 適格でない中間記録の辺は使わない | TE-L3、MB-L3、TM-L3 | 未確認の中間辺を介した推移的な除去は含まない |
| G4 | 訂正元の区間の外では、元の主張を除かない。全体訂正の後で期間を絞る方式は、この外側を消す | 区間が包含される訂正だけを許す | TE-L2、TM-L2（反例：C05・C06） | 未知能力・期間不明による停止を無視した非干渉ではない |
| G5 | 有限個の既知境界の間では所属が一定なので、境界と代表点を調べれば、この有限の記録集合・時点 k について全ての対象時点の判定を被覆できる | 半開区間、有限の記録集合 | TE-L4、TM-L5 | 任意の期間、臨床的な持続、時間論理一般の証明ではない |
| G6 | 有理数の正の倍率の換算は可逆で、大小と等号を保つ。非空の有限区間の関係集合は三条件で必要十分 | 正確な有理数演算 | QT-L1〜3 | 原字句、測定の不確かさ、負の倍率・オフセット・対数 |
| G7 | 同じ参照は一つの変数（自己比較で等しい）、別の記録は別の変数 | 局所 ID が選択した記録版に単射 | QT-L4、MB-L4 | 別記録間の相関は表さない |
| G8 | 丸めセル全体で一定の問いは artifact から定まる。同じ artifact に異なる原回答が対応する受理可能な二入力があれば、その問いは artifact に因子化しない。可逆な符号化は、先に失った区別を回復しない | 固定した丸め・セルの判定 | DP-L2〜4、TD-L2〜4 | 有限入力上限を使った完全な判定ではない。入力族を狭めると反例は自動では一般化しない |
| G9 | 専用のスキーマを追加し、旧核・旧 handler を変更しなければ、旧観測を保持できる構成になる | 共有 validator を変えない | TE-L5、MB-L6、DP-L5、TD-L5 | 設計だけの証明ではなく、回帰（§4.2）が要る |
| G10 | 個別に保存的な拡張でも、併用が保存的とは限らない（K04 型）。単項述語の分割では、併用全体の公理の下で全数に判定できる | 単項述語、分割4件・記号10まで | P2-c の導出（[25](25-p2-c-design.md)） | 多項述語、情報を失う段を含む鎖 |
| G11 | 固定した snapshot・k・依存版が残れば、同じ選択を再現できる | 元の要求と実装が保持される | MB-L6、TD-L1 | 保存先、旧実装の可用性、認証は保証しない |

整理の途中で、契約の枠が足りなかった点が繰り返し出ています。次は仮説の根拠になります（§5）。

### 6.2 選定：C1「未知期間の精密化」を最初に

vision の変化類型に対して、これまでの検証範囲は次のとおりです。

| 変化類型 | これまでの検証 |
| --- | --- |
| 新しい概念・属性・関係 | 分割（P2-b）、数量（P2-f）、期間（P2-e） |
| 新しい表現形式・領域 | 数量、表示（P2-h・j） |
| 定義・知識の修正 | 分割の一断片のみ。**確認済みの不完全な情報を後で精密化する経路は未実装** |
| 用途・制度・地域の違い | 表示射影が一つの模擬。複数の用途・出力先を同時に扱う実験はない |
| 記録の訂正・撤回・不一致 | 訂正・競合は検証済み。**撤回は P2-g で未対応と明記**（[39](39-p2-g-results.md)）。ほかの拡張にも専用の撤回の操作はない |
| 実装・機器・AI の変更 | AI 出自の保持と版の固定のみ。実装の差し替えの実験はない |
| コア仕様の改訂 | P0 の draft-1 → draft-2 の再現のみ（P2-d）。P2 の拡張の版更新は未実施 |

**C1 を選ぶ理由**：現在の設計は、確認済みの期間不明記録を、後から期間既知の記録で精密化して阻害を解消する経路を**持たない**と明記しています（[31 の §3.1](31-p2-e-design.md)）。一方 P2-g は、文脈の不明（例：方法不明）を、新しい記録・新しい内容確認で精密化できます（M33）。つまり、**瞬間では成り立つ精密化が、期間では、部分訂正が要求する区間の包含検査が期間不明では実行できないために成り立たない**、という二つの原理（精密化と部分訂正）が衝突する点が、既にはっきりしています。これは H1（選択の順序と確認対象を接続ごとに定める必要）と H7（追加情報として扱う設計が保てるか）を、外れ得る形で試せる最小の課題です。

**C2 を後にする理由**：縦断比較は、時間相関・比較可能性・臨床的な意味が一度に入り、反例を先に作りにくく、未知期間の扱いを前提にします。C1 の結果を使ってから設計するほうが、不足を切り分けられます。

**併走する小さな課題**：C6（拡張の版を上げる）は規模が小さく、コア仕様の改訂という未検証の変化類型に当たります。C1 の設計と並行して、版の手順を P2 の拡張へ適用する準備ができます。

### 6.3 C1 の設計の出発点（実装前の予測と反例）

次は実装の前に固定しておく予測と反例の候補です。いずれも未実施で、設計時に見直します。

**予測**

| ID | 予測 | 外れた場合 |
| --- | --- | --- |
| Y1 | 精密化は新しい記録と新しい確認として追加でき、旧い記録・確認・計算根拠は消えない | H7 が崩れる。元の記録を書き換える必要が出る |
| Y2 | 精密化の前後で、`unassessed` が決定へ変わるのは許されるが、決定済みの答えは、適格な訂正辺を通さずに追加情報だけでは変わらない | 情報の追加が決定済みの答えを変えるなら、G1 と G3 の前提が足りない |
| Y3 | 参照時点 k を精密化の前に取れば、精密化前の結果（阻害）を再現できる | 過去の参照時点の再現（G11）が壊れる |
| Y4 | 精密化の確認が到着する順序によらず、同じ k では結果が同じ | 順序依存なら、確認の到着順を状態として持つ必要がある |

**反例の候補**（実装より先に手で期待を指定する）

| ID | 内容 | 試すこと |
| --- | --- | --- |
| R1 | 記録 A は期間不明で確認済み。後から B が A の期間を [1,5) と精密化する。時点 t=3 と t=7 で問う | 精密化を「A の期間を B の区間に置き換える」と読むか、「B を A の訂正として追加し、A の不明は t=7 でなお阻害する」と読むかで、t=7 の答えが変わる。**どちらを採るかは、記録についての記録（第二階の主張）を契約が許すかという問いになる** |
| R2 | 二つの精密化 B・B' が A に対して食い違う区間を主張する | 競合を保つか。確認の順序で優劣を付けないか（latest-wins の変異を検出できるか） |
| R3 | 精密化の確認が、精密化前の計算根拠を無効にするか | 過去の k での結果が変わらないこと（Y3） |
| R4 | 精密化の区間が、A の訂正対象の区間に包含されない | 包含検査が、不明な区間に対して三値になるときの停止の順序 |

R1 は、現在の契約に「記録の期間という属性を、後から別の記録が確定する」操作を表す枠が無いことを示唆します。その場合は、契約のクラス表（H5）または七欄（H1）のどこに足すかが、不足の明確な証拠になります。

### 6.4 この後の順序
