## 4. 分かったこと

1. **組み合わせが決める4つのこと。** 独立な変数、比較可能性（文脈の一致）、方向と順序（同じ slot・前→後）、接続面の閉包。どれも P2-i と P2-f の個々の義務にはなく、断片を結ぶ側で決める必要があった（H4）。
2. **合成では主題 A〜H だけでは足りない。** 12の個別義務のうち8が A〜H、3が意味固有、1（LC-12）が「接続面の閉包」で、これは前段の出力が後段の入力の制約を満たすかという新しい主題だった。P2-k では新しい主題は要らなかったので、単独の能力と断片の合成で、義務の主題の組が違う可能性がある（H2）。1回の観察。
3. **接続面の閉包は意味の誤りではなく、数値の上限の差である。** P2-i の出力（約分した有理数、中間256bit）は P2-f の入力（63bit）として常に有効ではない。止まるのは安全側で、元のリテラルへ切り替えると P2-i の選択と換算の連鎖を飛ばす。目標単位の選び方で止まる・止まらないが変わる。
4. **継承は依存と別の関係。** 文脈の判定は P2-g の観点を再び述べたもので、P2-g を読まないので `depends_on` にも書かない。P2-g の変更で `affected()` が P2-m を列挙しないのは、宣言の書式が継承を表せないため（H8 の根拠の追加）。
5. **再固定の連鎖は手で保つ一覧（F4）。** 一覧から P2-m を外しても、既存の全検査が通った。仕様の内容から連鎖を求める検査（[test_quantity_version.py](../../tests/p2/test_quantity_version.py)）を足し、外すと失敗することを確認した。
6. **依存する拡張が増えるほど、依存される側の改訂が広がる（F5）。** P2-i の仕様の hash を含むファイルは、P2-i の例148、P2-j の例170で318、P2-m の例103で421になった（ほかに実装3・宣言1・台帳1）。P2-m を足したことによる既存ファイルの変更は 0。P2-i に比較を足す案（版を上げる案）なら、P2-j の170例を含む、hash を持つ既存のファイル318件を再固定することになる。
7. **未完了行の値の検査は欄名の一覧に依る（F6）。** 漏れの注入検査で、空配列・false の漏れが初回に検出されなかった。値を持たない行の検査を `is not None` に広げ、変異 B17 を足した。P2-h・j に続く三度目。
8. **版の更新の予行。** 数量の仕様に単位を一つ足す改訂を、コピーした木で行った。再固定の道具（連鎖に P2-m を載せた状態）と生成器だけで、P2-m の103例は hash の値を除いて同一になり、全て通った。手編集は連鎖への1行だけ。

### 実装の最中に直した誤り

- **手計算の誤り2件**：生成器の料金 L32（53→52）と L33（49→51）。実行前の見直しで式から再計算して見つけ、L32 は最初の置換が当たらず、実行で1件の不一致として現れた。いずれも設計57の表の値ではなく、生成器の転記の誤り。実装の出力に合わせたのではなく、式（設計56の§6）から再計算した値に直した。
- **検査の2件**：認定票に host が `certifier` 欄を足すことを、完全一致で比べて見落とした（比較を欄ごとにした）。未完了行の漏れの検査の穴（上記7）。

## 7. 限界と次

- 三点以上の傾向、差の大きさ、変化率、基準範囲、臨床的有意性、別 slot（別の部位・個体）、別 view（知識の変化）の比較は未対応です。関係の集合の推移を導くことも行いません（L44 は三点の組を二つずつ比べるだけ）。
- 「独立な変数」は、P2-i が時間相関を追加しないことに合わせた方針で、同じ記録の二時点の値が同じ未知値だという方針は範囲外です（`unsupported_comparison_policy`）。その方針を足すかは、医学的な意味を含むので別の判断です。
- 文脈の判定は property・specimen・method の一致だけで、同等性の推論（別の方法だが同等、など）はしません。
- 設計者・実装者・検査の作成者が同一で、独立確認はありません。手指定の期待と別計算が同じ読み違いを共有する可能性が残ります。
- 次の候補は、複数の出力先への射影（C7）、実資料評価と薄い臨床ライブラリの試作範囲の選定、継承を宣言する欄（H8）を契約に足すかの判断です。後者は契約の書式の変更を伴うので、着手前に利用者の確認を取ります。独立確認は将来の英語の別リポジトリで行います。
