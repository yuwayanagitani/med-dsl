## 4. 分かったこと

1. **要求を宣言にすると、出力先の追加はデータの追加になる。** 版 v1→v2→v3 の差は、足りない欄の数に等しい依頼の数としてそのまま出た。この性質は、27台帳の全数と、fixture にない出力先で確かめた有限の結果で、任意の出力先についての保証ではない。
2. **「表せない」と「足りない」と「評価できない」を分けると、行ごとの状態の優先が要る。** 優先（unassessed > not_representable > needs_information）は設計63で先に決めたが、**事前の手指定の表に、この優先を試す例がなかった**（F13）。
3. **AI 由来の候補を要求の充足から切り離すのは、構造で守れる。** 選択は人の確認を持つ記録だけで行い、候補は依頼の `candidates` にだけ出る。これは本ライブラリの設計の性質で、AI の生成の正しさとは無関係である。
4. **継承の宣言（P2-n）は新しい拡張に自然に使えたが、探索は外れる。** 3項目16証人を宣言できた。機械的な探索は、宣言した2組（temporal-display、longitudinal）のうち1組しか見つけなかった（F12）。
5. **接続面の閉包は、前段の出力を後段の入力にしない構成で避けられた。** 比較に渡すのは P2-i の換算領域でなく元のリテラル。これは P2-m の F7 に対する、設計上の別解の一つ。ただし、元のリテラルの検証を P2-i に頼る構成なので、本ライブラリは P2-i の検査を経たリテラルしか比べられない。
6. **操作の不正は P2-i の検査に頼って報告される。** 無効な訂正（有界でない期間、元の期間の外）や時刻の順序の誤りは、P2-i の理由（`unsupported_revision_scope`、`invalid_revision_interval`、`review_precedes_record`）と P2-i の欄の位置（`record.revises` など）で返る。ライブラリの欄名（`operation.corrects`）では返らない（F16）。理由は安定しているが、操作者向けの文言ではない。

### 実装の最中に直した誤り

- **実装の誤り1件**：F14（`origin.kind` の型）。
- **事前の表の穴1件**：F13（O08・O09 を追加。64 に追記）。
- **検査側の誤り**：乱数の要求の生成が、無効な訂正（unknown の期間への訂正）を作っていた。P2-i の制約に合わせて、期間不明は単独の記録に限った。ledger の改ざんの検査は、確認のない記録を改ざんして拒否を期待していた。確認のある記録を対象にした。関係の組の件数の期待値（15×15）を、大きさ18個の実際（18×18）に直した。いずれも期待を実行結果に合わせて黙って変えたのではなく、検査自身の前提（P2-i の制約、確認の有無、大きさの個数）を確かめて直した。
- **同値な変異の記録**：選択の探りに使う単位 `PROBE_UNIT` を替えても、全 fixture で子の計画の入力 hash 以外の結果は同じだった。検出の対象でなく、同値な変更として検査に残した。

## 5. 検査の強さ

- **別計算との比較**：27台帳×3対象時点×5問い合わせの全数（405行）、乱数400要求、固定例。実装と別計算は、状態・理由・依頼・出力・流れ・要素の状態・選択の記録・料金で比べた。別計算は P2-i・P2-f・P2-j の別計算を再利用するので、**それらの読み違いは共有する**。
- **差分**：丸めは41値×7分母×7桁数の2,009点を P2-j の実装と直接比較、関係は18×18の324対を P2-m の実装と比較、文脈の規則は method の版の違いを P2-m と比較、料金 C は P2-i の例を直接実行した実費と比較。
- **変異**：**26件**。関数の一時的な差し替え23件（文脈の判定の省略、推測の補完、候補の数え込み、single_point の検査の削除、次元・語彙の無視、後勝ち、保留中の訂正を依頼しない、suspected の確認、能力の無視、優先の入れ替え2種、half-up、表せない行の流れ、文脈の比較の削除、`ends` の取りこぼし、選択の検査の削除、不足以外の行の依頼、出自の消失、先払いの削除、完成料金の削除、推測で補った情報、認定の誤り）と、定数3件（fee、換算の予約、比較の予約）。全件検出（各変異は、狙った例の手指定の期待で失敗することを確かめた）。
- **検査器の変異**：B09・B15・B17・B18 を実行（結果は§6）。
- **子の呼び出しの注入**：P2-i の資源停止（部分結果は拾わない）、P2-f の資源停止（2行目で原子的）、P2-i・P2-f の実費の不一致を注入し、いずれも期待どおり。
- **型破損**：要求の全120ノード×6種の値（null・false・0・空文字・空配列・空object）で、状態は ok／invalid_input／unsupported_profile／resource_limit のいずれかで例外なし。入力不正は予算に依らず同じ結果。
- **接続面**：分子 `2^63−1` の二点の比較、丸め文字列の上限の注入。
