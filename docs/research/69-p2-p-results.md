## 4. 分かったこと

1. **構造の事実を仕様の表に出典のハッシュ付きで持つと、どの事実がどのページの記述に由来するかを辿れる。** ただし、事実の正しさ（ページの記述を私が正しく読んだか）は、同じ作成者の目の検査に限られる。目印の語がページに存在することの検査は、取り違えを防ぐだけで、意味の検証ではない。
2. **表せない理由を区別して返すと、失う区別を行ごとに残せる。** 丸め・閉じる・潰す・補うのどれもせず、理由ごとに `exact_value`・`interval_bounds`・`interval_width`・`validity_end` を失うものとして返す。
3. **仮定を足す規約は、呼び出し側が宣言したときだけ使い、足したことを流れに残す。** 期間の端の規約（`exclusive_end_as_last_second`）は秒の粒度の上でだけ正確で、FHIR の dateTime の精度の意味づけは検証していない。
4. **合成は既存を変えずに足せた。** P2-m の閉包の問題（前段の出力を後段の入力にする不整合）は、この拡張では起きない（出力を入力に戻さない）。
5. **運べない区別は、ライブラリの出力でなく、出力先の構造の側に原因がある。** 確認・出自・文脈の三状態は、取得した Observation のページの要素では運べない（Provenance・拡張は別）。この拡張はそれを `lost` に残すだけで、運ぶ方法は決めない。

## 7. 限界と次

- **構造は一つだけ**（`fhir-r5-observation`）で、判定は値・期間・文脈の運び方に限ります。`status`・`code`（必須の要素）、値のない記録（`dataAbsentReason`）、検体の状態、Quantity の `comparator`、コード化した単位、Provenance への出力、`Timing`・`instant`、他の資源は範囲外です。FHIR の資源の生成も、適合の検査もしません。
- **「18桁」の数え方**は、ページの記述だけでは決まらず、保守側の解釈（先頭の 0 を数える）を採りました。FHIR が許す境界とは主張しません。
- **期間の規約**は、ライブラリの時刻が秒の粒度であることに依ります。FHIR の dateTime の精度の意味づけは検証していません。
- **ページを読んだのは作成者一人**です。事実の読み違いは、同じ作成者の目の検査（目印の語、台帳のハッシュ）では見つかりません。別計算も P2-o の別計算を再利用しています。独立確認はありません。
- **医療者の負担が減ることの証明ではありません。** 構造への写像の可否を診断する一つの断片です。
- 次の候補は、`status`・`code` の写像と Provenance への出力（取得済みのページで読めるが、判断が要る）、CPC の版の監査、複数の出力先への射影の拡張です。着手前に利用者の確認を取ります。独立確認は将来の英語の別リポジトリで行います。
