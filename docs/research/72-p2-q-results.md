## 4. 分かったこと

1. **意味の判断を宣言に委ねると、ライブラリは判断をせずに使える。** `status`・`code`・確認者の型はライブラリが決めず、足りなければ依頼になる。使った判断は、仮定として行ごとに残る。宣言を作る人が負う判断（人の確認を「完了で追加の行為が要らない」と読む、など）の重さは、ライブラリには見えない。
2. **許容集合を、ページの定義から導くと、原本の `status` の選択は事実上一つになる。** `original` は `final` だけなので、その宣言は選択でなく、仮定を記録する儀式になる。本当の選択は訂正の `amended`／`corrected` だけ。許容集合が保守的すぎる可能性がある（`preliminary` など）。この読みは作成者のもので、別の読みを拒否する根拠は薄い。
3. **Provenance は、行為者が分かるものしか出せない。** `agent` は 1..* で必須。ライブラリの記録は、出自の種類と参照（AI なら Device）は持つが、**観察した人は持たない**。観察者が不明な記録の生成の Provenance は出せず、確認だけが出る（F23）。
4. **依頼の宛先が二種類になった。** P2-o の依頼は医療者への追加の観察・確認。P2-q の依頼は、出力先の宣言を作る人への宣言の追加。形も別（4欄）。同じ `needs_information` で宛先が違うので、利用側は依頼の種類で見分ける必要がある。

## 7. 限界と次

- **構造は一つだけ**（`fhir-r5-observation`）です。Provenance の `entity`（revision）、`activity` の符号、`agent.type`・`role`、署名、`status` の他の値、`code` の符号の系の検証、FHIR の資源（JSON）としての生成と適合の検査は範囲外です。
- **`status` の許容集合**と**確認者の型の選択**は、ページの定義の保守的な読みで、作成者のものです。人の確認を `final` とする判断は、宣言の判断であり、このライブラリの主張ではありません。
- **観察者を持たない記録**は、生成の Provenance を出せません（F23）。記録モデルの変更は別の判断です（その後 P2-r で任意の観察者を足しました：[75](75-p2-r-results.md)。観察者のない記録は引き続き存在し、生成の Provenance は出ません）。
- **ページを読んだのは作成者一人**です。別計算も P2-p・P2-o の別計算を再利用しています。独立確認はありません。
- **医療者の負担が減ることの証明ではありません。**
- 次の候補は、観察者を記録モデルに足す判断、revision の entity と activity の符号（その後 P2-t で実施：[81](81-p2-t-results.md)）、CPC の版の監査、複数の出力先への射影の拡張です。着手前に利用者の確認を取ります。独立確認は将来の英語の別リポジトリで行います。
