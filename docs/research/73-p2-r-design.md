## 2. 設計判断

| 判断 | 初回に採る設計 | 理由・見直す条件 |
| --- | --- | --- |
| RD1 | 記録に**任意の項目 `observer`** を足す：`{kind: human|device, ref}`。省略は「観察者不明」で、旧入力と同じ意味。必須にしない | 旧い記録を無効にしない。観察者が分からない記録は現実に多く、不明を不明のまま持つ（推測で補わない）。見直す条件：観察者を必須にする要求が出たとき（版を上げて旧入力を拒否する） |
| RD2 | 観察者は**記録の内容の一部**：確認が拘束する内容の hash に含まれる。観察者を後から書き換えた記録の確認は無効 | 誰が観察したかは、確認した内容の一部。出自（`origin`）と同じ扱い |
| RD3 | 選択された記録の根拠（P2-i の `binding_evidence.selected[]`）に、観察者があるときだけ `record_observer` を出す。省略のとき、キー自体を出さない | 観察者のない既存の入力の結果が変わらない。値が null のキーを全結果に足すと、全ての結果が変わる |
| RD4 | P2-o の操作 `record`・`correct` が任意の `observer` を受け取り、そのまま台帳へ渡す。選択の根拠に `record_observer` を、あるときだけ出す。確認の操作は観察者を持たない。検査は P2-i の検査に任せる | 台帳の妥当性は P2-i の再実行で検査する（CL-2）。P2-o は再実装しない |
| RD5 | P2-p は変更しない（選択の根拠をそのまま通すだけ）。P2-j・P2-m も変更しない（仕様の hash の再固定だけ） | 影響は再固定だけの拡張を、再固定として測る |
| RD6 | P2-q は、記録に観察者があり、Provenance を宣言したとき、**生成の Provenance**を出す。agent は、観察者が `device` なら Device、`human` なら宣言された型（`provenance.observer_type`。確認者の型と同じ集合）。人の観察者で型の宣言がなければ、推測せず依頼 `declare_observer_type` を返す。AI 由来の記録では、生成の Provenance の agent に、AI（Device）と観察者の両方を入れる | P2-q の「ライブラリは判断せず、宣言を使い、足りなければ依頼」と同じ。観察者がない記録は、これまでどおり（AI 由来のときだけ生成を出す） |

| RD8 | 再固定は、再固定の道具（依存の順に hash を再計算）と、実行例の生成器で行う。手編集をしない | P2-l の VD4。派生した hash（確認が拘束する内容の hash）は、置換では再固定できない |
| RD9 | 版の記録は `p2-version-record-draft-2`。旧入力の扱いを三つに分ける（P2-l の VD7）。旧版のコミットは `dc0aabe`（P2-q の直後） | 手順を変えずに、規模だけを変える |

## 3. 変更の内容

### 3.1 P2-i（期間つき数量）

- 記録の項目に任意の `observer` を足す。形：`{kind, ref}` の完全一致（欠落は `missing_field`、余分な欄は `unknown_field`）。`kind` は `human`・`device` のどちらか（それ以外は `invalid_observer`）。`ref` は空でない文字列。
- 内容の hash は、記録の JSON 全体を含むので、`observer` を持つ記録は持たない記録と別の hash になる。`observer` を持たない記録の**記録自身の内容**は変わらないが、hash の入力に仕様の hash が含まれるため、**全ての記録の hash が変わる**（仕様の hash の変更によるもの。Q4）。
- 選択された記録の根拠に、`observer` があるときだけ `record_observer` を出す。
- 課金・停止・選択の規則・回答の形は変えない。

### 3.2 P2-o（臨床ライブラリ）

操作 `record`・`correct` の任意の `observer` を台帳の記録へ渡し、選択の根拠（`selection`）に、あるときだけ `record_observer` を出す。他は変えない。

### 3.3 P2-q（Observation の写像）

- `observations[].provenance` に任意の `observer_type` を足す（許容は確認者の型と同じ4種。それ以外は `unsupported_observer_type`）。
- 生成の Provenance を、(a) 出自が `ai_candidate`、または (b) 観察者がある、のとき出す（Provenance の宣言があるときだけ）。agent は、AI（Device、出自の参照）、観察者（`device`→Device、`human`→宣言した型）の順に、あるものを入れる。`recorded` は記録の時刻。
- 人の観察者で `observer_type` がない行は `needs_information`。依頼 `{element: provenance, action: declare_observer_type, record_ref, property_ref: null}`。
- 流れ：観察者のある記録で、Provenance を出すとき `observer` を保持に、出さないとき `observer` を失うものに。人の観察者の型を使ったとき、仮定 `assumption:observer_type_declared` を足す。観察者のない記録の流れは変えない。

| 拡張 | 現在 | 変更後 | 変更の種類 |

## 5. 版の手順（V1〜V8）

P2-l の手順をそのまま使う：V1 旧版の保持、V2 旧版の契約での再現、V3 版の記録で変更を宣言、V4 旧入力は新版で黙って再解釈されない（旧い pin は `profile_spec_mismatch` で拒否）、V5 再固定した入力は旧入力と同一（hash の値を除く）、V6 旧版の結果と新版の結果（再生成した入力どうし）の差は宣言した変更だけ、V7 再検証の範囲（`affected()` と実測）、V8 前方の互換（新版で追加した項目を使う入力を旧版の木へ渡すと、旧版は黙って無視せず拒否する）。

## 7. 受入条件

1. [74](74-p2-r-cases.md) の期待・予測・反例を、runtime より先に保持し、実行結果から期待を更新しない。
2. 変更は P2-i・P2-o・P2-q に限り、P2-j・P2-m・P2-p は仕様の hash の再固定だけ（実装の論理を変えない）。再固定は道具と生成器で行い、手編集をしない。
3. 版の記録を作り（`p2-version-record-draft-2`）、V1〜V8 を比較器と履歴の検査で確かめる。宣言にない差は失敗にする。
4. P2-i・P2-o・P2-q の新しい実行例、別計算の更新、変異（観察者の hash への不算入、`record_observer` の欠落・誤出力、型の推測、生成の Provenance の誤出力）を検査する。
5. Python 3.11／3.14 で、全テスト系列、版比較つき統合評価、旧い22,052件の挙動 digest を回帰する。分母の変更は旧い値を履歴として残す。
6. 追加前は `dc0aabe`（P2-q の追加後）、固定対象1702ファイル、manifest `89cb715d68bf84f41e78fd9701c58dc51f5e906af46cd2d0926414ae8f0dcd5a`、束 `7b13731aed3779ab8f238713e0ae6747fd7832055014ad62611857ed64594c1d`。件数・hash・予測の結果・残る穴を結果の文書に残す。`independent_review` / `evaluation_frozen` は false。

## 8. 範囲外

観察者の同一性の管理（同じ人かの照合、権限、資格）、観察者の履歴（変更の記録）、観察者を必須にする版、観察の道具（機器の校正など）、P2-g・P2-k など P2-i 以外の拡張の記録モデル、実在の識別子体系。

この設計は、記録モデルの変更が下流へ及ぶ様子を測る一つの実演で、観察者の記録が実際の運用に足りることの証明ではありません。最終目標は変化に耐える医療コード体系そのものの確立であり、この有限の設計はその一つの検査です。
