## 4. 分かったこと

1. **任意の項目の追加は、意味の局所性と、ファイルの規模が別物であることを示した。** 意味が変わる入力は新しい25件だけで、旧入力737件の結果は変わらない（hash の値を除く）。一方、書き換わったファイルは813件で、P2-l の単位表2行の改訂（739件）より多い。hash が固定する依存の木が大きくなったため（F5 の続き）。
2. **観察者を hash 付きの記録の内容にすると、確認と観察者が結ばれる。** 観察者を確認の後に変えると、確認は無効になる。記録の hash は仕様の hash を含むので、仕様を改訂すると全ての確認が無効になる（旧い確認は新版へ引き継がない、という既存の規則のとおり）。
3. **記録モデルの穴は直った。** 観察者が分かる記録は、生成の Provenance を出せる。分からない記録は、これまでどおり出せない（F23 の続き：観察者を持たない記録は、依然として存在し得る）。
4. **意味の変更の宣言は、書式を変えずに書けた。** 宣言の種類 `added_field` は、P0 の draft-2 の更新（P2-d）の先例で足りた。ただし、比較器は追加した入力の読み方を一般化する必要があった。

## 7. 限界と次

- **観察者は2種（human・device）の任意の項目**だけです。同一性の管理（同じ人かの照合、資格）、履歴、必須にする版は扱いません。訂正は元の観察者を継ぎません。
- **観察者のない記録は、これからも存在します。** 生成の Provenance は出せず、`observer` は失うものに残ります。
- **版の手順は、1つの更新（任意の項目の追加）の実演**です。項目を必須にする更新、項目の意味の変更、削除は試していません。
- **比較は有限の旧入力**（737件）に基づき、旧入力が行使しない新版の変更（観察者）は旧入力の比較では見えません。一般の保存の証明ではありません。
- 設計者・実装者・検査の作成者が同一で、独立確認はありません。
- 次の候補は、項目を必須にする更新（旧入力を拒否する版の更新）、revision の entity と activity の符号、CPC の版の監査です。着手前に利用者の確認を取ります。独立確認は将来の英語の別リポジトリで行います。
