# P2-s：任意の項目を必須にする版の更新（旧入力を拒否する）の設計

作成日：2026-10-21。状態：**作成者側の設計草案。実装・版の記録は未作成**。[P2-r の結果75](75-p2-r-results.md) が試したのは「任意の項目を足す」更新（旧入力はそのまま有効）でした。P2-s は逆向きの、**旧入力を拒否する更新**を試します。P2-r で足した `observer` を必須にし、不明は「不明」と明示する値（`kind: unknown`）で書かせます。旧入力は新版で受理されず、移行（旧入力に明示の不明を足す）を経て初めて有効になります。利用者の指示（2026-10-21「項目を必須にする版の更新（旧入力を拒否する）」）に従います。手指定の期待は [77](77-p2-s-cases.md)。独立確認・評価用正解の凍結は未実施で、`independent_review` / `evaluation_frozen` は false のままです。数値・識別子はすべて架空です。外部資料は新たに参照しません。

## 1. 問い

| Q1 | 任意だった項目を必須にしたとき、旧入力は**黙って受理されず、欠落した必須項目という理由で**拒否されるか（pin の置換だけで通る入力は 0 か） |
| Q2 | 旧入力を新版の入力へ移すこと（移行）が、**意味を変えずに**できるか。移行は「不明を明示する」だけで、推測で値を補わないか |

| Q5 | 新版の入力を旧版の木へ渡すとどうなるか。互換の部分集合（旧版が受理する新入力）はあるか |

## 2. 設計判断

| 判断 | 初回に採る設計 | 理由・見直す条件 |
| --- | --- | --- |
| SD1 | 記録の `observer` を**必須**にする。形は `{kind, ref}` の完全一致（`kind` が `human`・`device`）か、**`{kind: unknown}`**（`ref` を持たない）。`unknown` は「観察者が分からない」を明示する値で、観察者を推測しない | 不明を欠落（黙った不明）でなく、記述（明示の不明）にする。必須にする目的は、答えを強制することでなく、「聞いたが分からない」と「聞いていない」を分けること |
| SD2 | 選ばれた記録の根拠の `record_observer` は、**常に出す**（不明のとき `{kind: unknown}`） | 必須の項目の値は、根拠から常に読める。P2-r の「あるときだけ」はやめる |
| SD3 | P2-o の操作 `record`・`correct` にも `observer` を**必須**にする。ライブラリは、省略を `unknown` で補わない。補う層を作るなら、操作の入口（画面など）の外に置く | 補完は「不明を確定する」判断。必須にする更新の意味を保つ。見直す条件：入力の負担が大きいと分かったとき（補完の層を別に設計する） |
| SD4 | P2-q：観察者が `unknown` のとき、観察者の agent も `declare_observer_type` の依頼も出さず、流れの `observer` も変えない（P2-r で観察者のない記録を扱ったのと同じ結果）。`record_observer: {kind: unknown}` は選択の根拠に現れるだけ | 旧入力の移行後の結果を、観察者の追加の前後で変えない |
| SD5 | P2-p・P2-j・P2-m は論理を変えず、再固定だけ（P2-j・P2-m は根拠をそのまま写すので、結果の中の根拠に `record_observer` が現れる） | 影響が再固定と根拠の写しだけの拡張を、そのまま測る |
| SD6 | 版：P2-i を draft-4 にし、依存する5拡張も一つ上げる：P2-j（draft-4）、P2-m・P2-o・P2-p・P2-q（draft-3） | P2-l・P2-r と同じ（版が変わらないまま hash が変わる状態を作らない） |
| SD7 | 移行は**生成器の既定の変更**で行う：全ての例の記録・操作に `observer: {kind: unknown}` を既定で足す。移行の規則は「欠落の記録に、明示の不明を足す」だけで、期待の値は変えない（結果の根拠に `record_observer` が増えることは宣言する） | 移行を手編集にしない。旧入力と移行後の入力の差を比較器で検査できる形にする |
| SD8 | 版の記録は `p2-version-record-draft-2` のまま、宣言の種類 `required_field` を足す。宣言は、(a) 要求の側で全ての入力に加わる項目の経路の接頭辞（`request_paths`）、(b) 結果の側で現れる根拠の経路の接頭辞（`result_paths`）、(c) 旧入力を pin の置換だけで渡したときの拒否の理由（`substitution_refusal`）を持つ。**比較器はこれを読めるよう拡張する**（書式でなく道具の変更） | Q3。拡張が要ることは予測（Z6）で、拡張の大きさを測る |
| SD9 | 前方の互換：新版の入力を旧版（draft-3）の木へ渡す。`unknown` を使う入力は旧版が `invalid_observer` で拒否する（未知の値を黙って受理しない）。人・機器の観察者だけの入力は、旧い pin に替えれば旧版が受理する（互換の部分集合） | Q5 |

## 3. 変更の内容

### 3.1 P2-i（期間つき数量）

- 記録の項目に `observer` を必須で足す（`fields` の必須欄）。欠落は `missing_field`。
- 形：`kind` は `human`・`device`・`unknown`。`unknown` のとき `ref` があれば `unknown_field`。`human`・`device` のとき `ref` がなければ `missing_field`（空文字は `expected_nonempty_string`、余分な欄は `unknown_field`、object でなければ `expected_object`、`kind` が別なら `invalid_observer`）。
- 根拠の `record_observer` は常に出す。内容の hash に観察者を含めるのは変えない。他は変えない。

### 3.2 P2-o（臨床ライブラリ）

操作 `record`・`correct` の `observer` を必須にして、台帳へそのまま渡す。選択の根拠の `record_observer` は常に出す。確認の操作は観察者を持たない（変更なし）。

### 3.3 P2-q

`selection.record_observer` の `kind` が `unknown` のとき、観察者を持たない記録と同じに扱う（SD4）。他は変えない。

## 5. 版の手順（V1〜V8）

P2-l・P2-r の手順を使い、V4・V5・V6・V8 を次のように読み替える。V4 旧入力を新版へそのまま渡す：pin で拒否される。V4′（置換）：旧い pin を新しい値へ文字列で置換した入力は、**欠落した必須項目（`missing_field`）で拒否される**。V5 移行した入力と旧入力の比較：要求の違いは、宣言した `observer` の追加だけ（hash の値を除く）。V6 旧版の結果と新版の結果（移行した入力どうし）：違いは、宣言した根拠の `record_observer` の追加だけ。V8 前方の互換：SD9。

## 7. 受入条件

1. [77](77-p2-s-cases.md) の期待・予測・反例を、runtime より先に保持し、実行結果から期待を更新しない。
2. 論理の変更は P2-i・P2-o・P2-q に限り、P2-j・P2-m・P2-p は再固定だけ。移行は生成器の既定の変更で行い、手編集をしない。
3. 版の記録を作り、V1〜V8 を比較器と履歴の検査で確かめる。比較器の拡張は最小限にし、その大きさを結果に記録する。宣言にない差は失敗にする。
4. 必須化の新しい実行例、別計算・テストの更新、変異（必須の検査の削除、`unknown` の検査、補完、`record_observer` の欠落）を検査する。
5. Python 3.11／3.14 で、全テスト系列、版比較つき統合評価、旧い22,052件の挙動 digest を回帰する。分母の変更は旧い値を履歴として残す。
6. 追加前は `ab4c358`、固定対象1,732ファイル、manifest `4aa13b97…`、束 `4861a082…`（先頭8桁。完全な値は結果の文書に写す）。`independent_review` / `evaluation_frozen` は false。

## 8. 範囲外

観察者の履歴・資格・同一性、`unknown` の細分（聞いていない／聞いたが分からない）、補完の層（画面など）、項目の削除・意味の変更、他の拡張の記録モデル。

この設計は、必須化の更新の影響を測る一つの実演で、`unknown` の値が実際の運用で足りることの証明ではありません。最終目標は変化に耐える医療コード体系そのものの確立であり、この有限の設計はその一つの検査です。
