設計の前に、取得済みの 2 版（`SAB=RXNORM`）の差を、面ごとの**件数だけ**で集計した。**以下は予測ではなく、既知の値**として扱い、予測（§8）は、まだ計算していない量と、契約の性質に限る。

| 面 | 既知の集計（9 月 → 10 月） |
| --- | --- |
| 概念 | 9 月 81,468、10 月 81,620。両版にある 81,298、9 月だけ 170、10 月だけ 322 |
| 原子 | 両版にある原子 140,535 件は、用語種別・文字列・抑制の欄が 1 件も変わっていない。変わるのは追加（539）と削除（306）だけ。続く概念で原子が増減したのは 3 件（-2、+1） |
| 概念間の関係 | 追加 1,932、削除 1,388。**すべて**追加・削除された概念につながる。両端が両版にある概念どうしの関係の変化は 0 |
| 属性 | 追加 2,521、削除 2,519（`(RXCUI, 属性名, 値)` の集合）。続く概念に対する追加 1,723、削除 1,887。大半は `NDC`（削除 1,844、追加 1,751）。強度に関わる属性（`RXN_AVAILABLE_STRENGTH`、`RXN_STRENGTH`、`RXN_BOSS_*` など）も一部変わる |

## 3. 設計判断

| 判断 | 初回に採る設計 | 理由・見直す条件 |
| --- | --- | --- |
| UD1 | **単独の専用 R5**を新設する（P2 系列の他の拡張に依存しない）。操作 `run_terminology_audit`：旧版の snapshot と新版の snapshot、比較範囲（出典）、属性の方針、監査する参照の列を受け、参照ごとの監査の行と、集計を返す。**一方向**（旧→新）。逆向きの成立を推定しない | D04 の一方向。クラス R5：保存を主張しない診断（変わる点を記録、認定を出さない、臨床の主張を足さない） |
| UD2 | snapshot は正規化した形：`concepts[]`＝`{id, source, atoms[{id, kind, name, attributes[{name, value}]}], relations[{kind, target}]}`。**概念の同一性は (出典, id)**。関係は**その概念から出る向き**で、向きの読み替えは呼び出し側（正規化）の責任。契約は向きを反転しない。属性は**原子に付く**。名前・属性名・値・種類は不透明な文字列で、内容を解釈しない | 実データの構造（原子に付く属性、行の向き）に合わせる。不透明にして、第三者の語彙の内容に触れない |
| UD3 | **継続**＝新版に同じ (出典, id) の概念がある。名称・属性・関係の一致は継続の判定に使わない。新版にないときは `not_found`、`successor: not_determined` で、後継の候補を一つも返さない。追加情報の依頼（`provide_official_history`）を返す | 名称の一致だけで概念を同一視しない（D03 の誤った扱い）。CPC は廃止・抑制された内容を含まないので、不在は廃止の証拠でない |
| UD4 | 比較する面は三つ：**名称**（原子の追加・削除・同じ id の種類／文字列の変更）、**関係**（`(種類, 対象)` の集合の差。対象が各版に存在するかの旗つき）、**属性**（両版にある原子の `(原子, 名前)` ごとの値の集合の差）。面を混ぜた推論をしない。追加・削除された原子に付く属性は、属性の差でなく、名称の差に伴う件数（`with_atom_change`）として数える | P-CPC-2 の期待（名称の変更を含量の変更と推定しない）。原子の増減と属性の増減を分ける |
| UD5 | **属性の方針は呼び出し側の宣言**：`policy.attributes[]`＝`{name, class}`、`class`＝`definitional`（定義にあたる）／`administrative`（管理上の情報）。ライブラリは属性名の意味を知らない。差のあった属性が未宣言なら、**差を `undeclared` に分けて依頼**（`declare_attribute_class`）にし、推測しない。使った宣言（差のあった属性）は `assumptions` に残す。使われなかった宣言は痕跡を残さない | P2-q の status・code と同じ規則。専門的な判断を実装が決めない |
| UD6 | 継続した参照の `state`（優先順）：`changed`（名称・関係の差、または定義にあたる属性の差がある）→`needs_information`（未宣言の属性の差がある）→`changed_administrative_only`（管理上の属性の差だけ）→`unchanged_in_scope`（比較した三つの面のどれにも差がない）。`not_found`・`not_compared`（出典が比較範囲の外）はそのまま。**`unchanged_in_scope` は「比較した範囲で差なし」で、意味の同一ではない** | 比較不能を差なしとして扱わない |
| UD7 | 関係の対象が新版に存在しない（未解決）ときは `unresolved_in_to`＝`{target, in_from}` に出す。旧版に存在した対象が新版で未解決なら関係の面は `changed`、旧版でも存在しなければ既存の状態として報告だけ | 依存の欠落を見逃さず、既存の不整合を差分に数えない |
| UD8 | 出力は参照ごとの行（`presence`・`state`・`facets`・`requests`・`assumptions`・`successor`）、比較範囲（出典・面・方針・比較していないもの）、集計（概念数・継続・旧のみ・新のみ・状態別の数）。認定は常に `not_certified`、推測で補った情報は常に空 | P2-q 以降と同じ |
| UD9 | 料金：M＝1＋n_from＋n_to＋Σ（参照ごとの料金）＋1。参照の料金は、比較範囲の外なら1、範囲内なら 1＋A_f＋T_f＋R_f（旧版の原子数・属性数・関係数）に、新版にあるときだけ A_t＋T_t＋R_t（新版の同じ数）を足す。n は snapshot の概念数。入力不正は予算に依らない。未完了の行は値の欄を null にし、集計も null | 手で導ける式 |
| UD10 | **実データの実行は契約の関数を直接呼ぶ**（JSON の大きさ・予算の限界を通らない）。実データの snapshot は、道具（`scripts/research/audit-cpc-versions.py`）が台帳のハッシュを確かめた ZIP から正規化して作る。正規化の写像（列の位置、行の向き、重複の除去、原子対原子の関係・原子に結べない属性の扱い）は、架空の RRF 形式の ZIP を使うテストで確かめる。実データの結果（行を含む）は Git 管理外の `data/research/r4/` に置き、文書には集計だけを書く | D03 の「生データを共有しない」 |

## 4. 入口と型（予約名）

| 項目 | 予約する型・範囲 |
| --- | --- |
| profile / operation | `p2-terminology-audit-draft-1` / `run_terminology_audit` |
| request / result | `p2-audit-request-draft-1` / `p2-audit-result-draft-1` |
| 回答型 | `terminology_version_audit` |
| 要求 | `schema_version, operation, consumer, from, to, scope, policy, references, budget` |
| from・to | `{ref, version, concepts[], source_sha256?}`。`ref` が同じ（同じ用語）で `version` が異なること |
| scope | `{sources[]}`（比較する出典。最大8） |
| policy | `{attributes[{name, class}]}`（最大64） |
| references | 旧版の概念 ID の列（最大256、重複なし、旧版に存在すること） |

結果の行（`results[]`、参照の昇順）：`reference, source, presence, state, facets, requests, assumptions, successor, assessment_complete, reason_codes`。`presence`＝`continues`／`not_found`／`not_compared`。`facets`＝継続の行だけ：`names{state, added[], removed[], modified[]}`、`relations{state, added[], removed[], unresolved_in_to[]}`、`attributes{state, definitional[], administrative[], undeclared[], with_atom_change{added, removed}}`。他は null。トップレベル：`direction: from_to`、`reverse_inferred: false`、`versions`、`scope`、`policy`、`summary`。

## 5. 判定の規則

1. 参照の (出典, id) が旧版にあり、出典が `scope.sources` にない→`not_compared`。
2. 新版に同じ (出典, id) がない→`not_found`（`successor: not_determined`、依頼 `provide_official_history`）。
3. あれば継続。三つの面を比べる：名称（原子 id をキーに、追加・削除・種類／文字列の変更）、関係（`(種類, 対象)` の集合。対象が各版に存在するか、新版で未解決か）、属性（両版にある原子の `(原子, 名前)` ごとに、値の集合が異なるもの。差を方針で `definitional`／`administrative`／`undeclared` に分ける）。
4. UD6 の優先順で `state`。未宣言の属性の差があれば、状態に依らず依頼を返す。

## 6. 七欄と義務の主題

| 欄 | 内容 |
| --- | --- |
| 前提 | 属性の分類は宣言（作り手の判断）。正規化（出典の行の読み方）は呼び出し側。契約は不透明な文字列を比べる |
| 版 | 自己の profile・仕様 hash を consumer が固定。用語の版は snapshot の `version` と任意の `source_sha256` |
| 確認対象 | 確認は作らない。参照の継続と面ごとの差を報告する |
| 情報の選択 | 比較範囲（出典・面）を明示。範囲外は比較しない |
| 問い | 「この参照は、新版でそのまま使えるか。何が変わり、何が判断できないか」 |
| 保持・喪失・追加 | 差の報告（追加・削除・変更）と、比較していないもの（履歴・意味・他の出典・原子間の関係・抑制）を明示。使った宣言を仮定として残す |
| 資源・停止 | UD9。停止の順序：静的検査→索引→参照ごと→最後の確定 |

義務（16：共通4＋R5の3＋AU-1〜9）：AU-1（A）自己の版と実体。AU-2（I）各参照がちょうど一つの状態に入る（分割）。AU-3（I）継続の同一性と、後継を決めないこと。AU-4（I）面を別に比べ、差なしの条件。AU-5（I）属性の方針と依頼。AU-6（I）関係の向き・対象の存在・未解決。AU-7（I）比較範囲と範囲外・集計。AU-8（F・E）料金・停止の順序・未完了行。AU-9（H）推測で補わない（後継・逆向き・意味）。予測（H2）：**主題の外の義務は出ない**（この契約は外部資料の事実を native に持たないため。実データの写像の事実は道具とそのテストが持つ）。

## 7. 実データの実行（道具）

`scripts/research/audit-cpc-versions.py`：台帳のハッシュで 2 つの ZIP を確かめ、`RXNCONSO`・`RXNREL`・`RXNSAT` の `SAB=RXNORM` の行を正規化して契約の関数に渡す。ZIP の展開・SQL の実行・通信は行わない。

| 正規化の写像 | 内容 |
| --- | --- |
| 概念 | `RXNCONSO` の `SAB=RXNORM` の行の `RXCUI`（出典は `RXNORM`）。原子＝`{id: RXAUI, kind: TTY, name: STR}`。同じ原子は一つ |
| 関係 | `RXNREL` の `SAB=RXNORM` かつ `STYPE1=STYPE2=CUI` の行を、**所有者＝`RXCUI2`**、種類＝`RELA`（空なら `REL`）、対象＝`RXCUI1` の関係とする（局所データで向きを確認済み）。同じ組は一つ。原子対原子の行は比較しない（件数を報告） |
| 属性 | `RXNSAT` の `SAB=RXNORM` かつ `STYPE=AUI` の行を、原子（`RXAUI`）に付く `{name: ATN, value: ATV}` とする。原子に結べない行・重複は件数を報告 |

実データの属性の方針は、**作り手の研究上の仮定**（医学的判断ではない）として二通りを宣言する：**P-full**＝`NDC` を `administrative`、データに現れる他の全ての属性名を `definitional`。**P-partial**＝`NDC` を `administrative`、強度に関わる属性名だけを `definitional`、他は未宣言。方針の違いが状態の分布をどう変えるか（感度）を測る。
