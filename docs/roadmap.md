# ロードマップ

状態：暫定。完了済みはリポジトリの初期化と初期文書の作成のみです。

## 0. 立ち上げ

- [x] 独立した Git リポジトリを作る。
- [x] README、設計メモ、調査課題を置く。
- [x] 非公開運用と外部データを分離する方針を記録する。

## 1. 最初の変換を定義する

- [ ] 先行仕様・実装を調べ、既存ツールを利用できる範囲を確認する。
- [ ] 対象領域、入力体系、出力体系、方向、版、国・地域、用途を一つずつ選ぶ。
- [ ] 外部データや対応表の取得方法・利用条件を確認する。
- [ ] 架空の評価ケースと、人が確認した期待結果を用意する。
- [ ] 技術スタックを決め、最小の実行環境を設定する。

## 2. 最小の翻訳機を試す

- [ ] 原コードと版を保持する最小の中間表現を作る。
- [ ] 候補、意味関係、情報損失、追加情報、根拠を返す契約を定義する。
- [ ] 限定した対応規則と CLI を実装する。
- [ ] 曖昧、未対応、情報不足、版違いを含めて評価する。

この段階の完了条件は、合意したケースで結果と限界を再現できることです。正解率だけでなく、根拠のない確定、失われた情報、確認が必要な件数も記録します。

## 3. 表現範囲を広げる

- [ ] 複合概念、因果関係、否定、疑い、既往、家族歴、時間を評価する。
- [ ] 単純な対応表と中間表現を介した方法を同じケースで比較する。
- [ ] 新しい対象体系と領域を加え、共通モデルの不足を記録する。
- [ ] 必要性が明らかになった時点で DSL、パーサー、意味検証を設計する。

## 4. 入力と運用を検討する

- [ ] 自然言語からの構造化と、人による確認の流れを試す。
- [ ] FHIR 連携などの交換形式を検討する。
- [ ] 入力負担、修正時間、追跡可能性、版更新時の再現性を評価する。

長期的な網羅性は、領域ごとの対応範囲と未対応ケースを積み重ねて評価します。
