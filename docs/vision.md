# 最終目標と設計原則

更新日：2026-10-18。状態：プロジェクトの目的と研究方針。以下の性質を実現・証明済みという意味ではありません。

## 最終目標

**未来永劫、原理的に変化に耐えうる医療コード体系を確立すること。**

医学的知識、扱う概念、記録の目的、制度、利用者、システム、AI が変化しても、それらを表現・拡張でき、既存の記録や概念の意味を追跡できる体系を目指します。特定の既存コードへの変換を、このプロジェクト全体の成功条件にはしません。

## 目的の階層

| 位置付け | 内容 |
| --- | --- |
| 最終目標 | 将来の変化を原理的に受け止められるコード体系そのものの確立 |
| 基礎研究・設計 | 何を変化として扱い、何を保つかを定義し、表現・意味・拡張・互換性の仕組みを設計する |
| 中間目標 | 既存体系の表現、コード移行支援、意味の保持・喪失・追加の監査を通じて設計を検証する |
| 応用・普及 | 臨床ライブラリの整備・標準化、医療者の操作と接続先の分離、AI が利用・検証できる情報整理 |

医療者と AI の利用は、基盤設計の初期要件として扱います。応用の実装を後に行うことを理由に、内部表現を当面の移行先や特定の AI の都合へ固定しません。

移行支援の試作が有用でも、それだけで最終目標を達成したとは判定しません。逆に、一つの移行例で利点が出ない場合は、例・実装・表現原則を見直し、プロジェクトを直接変換ツールへ置き換えて完了とはしません。

## 最初に定義すること

「変化に耐える」の意味を研究対象として明確にします。以下は要件の候補で、最終的な形式や実現方法は未決定です。

| 変化 | 保ちたい性質・検証する問い |
| --- | --- |
| 新しい概念・属性・関係の登場 | 既存体系の分類枠に無理に押し込めず、意味を定義して追加できるか |
| 新しい表現形式や領域の登場 | 文法・型・概念モデルのどこを拡張すればよく、その手順を体系として定義できるか |
| 医学的な定義・知識の修正 | 過去の定義と現在の定義を区別し、何が改訂されたか追跡できるか |
| 用途・制度・地域の違い | 同じ事象に対する複数の分類・記録・会計上の見方を分けて表現できるか |
| 記録の訂正・撤回・不一致 | 当初の記録と後の判断、異なる主体の主張を混同せず扱えるか |
| 実装・機器・AI の変更 | 特定製品や表示形式に意味を依存させず、別の実装でも解釈と検証ができるか |
| コア仕様自体の改訂 | 変更が必要な場合の互換性、旧記録の解釈、情報の保持をどう規定するか |

既存の意味を保存することと、新しい知識に基づく判断へ更新することを両立する方法を調べます。過去に記録された主張を保持することは、その主張を現在も真と扱うことではありません。

## 設計を導く原則

- 特定のコード体系、国、制度、診療科の分類枠を普遍的な基礎と決めつけない。
- 識別子、概念の意味、記録上の主張、情報源、表示名、外部体系への対応を分けて定義する。
- 拡張の方法と、何が変わらないべきかを、個々の接続先の実装より先に検討する。
- 新たな意味を定義できたことと、未解釈のコードや文章を保存できたことを区別する。
- 比較不能や未対応は正直に報告し、それを意味の網羅性を達成した証拠には使わない。
- 既存の規格・論理・モデル・実装は、最終目標に必要な性質を満たすために評価・再利用する。
- 素のコードや DSL の手入力を医療者に要求せず、臨床ライブラリ・画面・AI との境界を設ける。

コアをどこまで固定するか、拡張をどの表現能力で受け止めるか、コア自身の改訂をどう扱うかは基礎研究で比較します。「改訂を管理できれば普遍性を達成した」とも、「すべての定義を初めから列挙しなければならない」とも、現時点では決めません。

## 原理と実証の分担

最終目標の「未来永劫」は研究の方向を定める要求です。根拠の提示は、対象とする変化、仮定、保つ性質を明示して行います。

| 根拠の種類 | 確かめること |
| --- | --- |
| 形式的な検討 | 定めた前提の下で、拡張・意味保存・互換性等の性質が成立するか。必要な制約や反例は何か |
| 実証・実験 | 異なる領域・体系・将来変化の模擬例で、設計どおり表現・拡張・解釈できるか |
| 運用評価 | 医療者の操作、実装間の適合、知識更新、AI 利用で、意味と根拠を保持できるか |

有限の実験結果を未知の全変化への保証と同一視せず、形式的に示せた性質と経験的に確認できた範囲を分けます。最終目標は維持したまま、到達した範囲と未解決の点を記録します。
