[R6 の P0](../docs/research/06-prototype-brief.md) は、[37 の架空 JSON 入出力例](p0/README.md) で P0 の全22ケースを具体化し、[P0-d](../docs/research/10-p0-d-results.md) で作成者草案の指定チェック221件を照合しました。S1/S2 の認定・推論、主張の確認・訂正・未知能力の停止、支持 binding の前後比較を含みます。116 件の開発テスト、P0 の22ケース、R4 の40件、独立・未見評価はそれぞれ分母を分けます。

## 体系そのものの変化への耐性

[最終目標](../docs/vision.md) に向けて、R2b で変化の種類と不変条件の候補を整理し、[R4](../docs/research/04-evaluation.md) で以下の例と K01〜K14 の評価方法を具体化しました。移行の成否だけで体系の普遍性・永続性を評価しません。

| ケース候補 | 確認すること |
| --- | --- |
| 新概念・新属性・新関係を追加する | 拡張方法が定義でき、既存の意味をどう保てるか |
| 新しい領域や記録目的を導入する | 既存の分類枠に無理に押し込めず意味を表せるか |
| 医学的な定義を修正する | 旧定義と新定義、過去の記録の解釈を追跡できるか |
| 記録を訂正・撤回し、主張が食い違う | いつ誰が何を述べたかと、後の判断を区別できるか |
| コア仕様・実装を変更する | 旧表現の解釈と互換性を、どの条件で保てるか |

## 中間用途としての移行・意味差分

| ケース候補 | 確認すること |
| --- | --- |
| 単一概念の一致 | 対象版と用途を指定した基本的な対応 |
| 左右や部位のある病態 | 属性の保持、情報損失、追加情報 |
| 原因疾患と続発病態 | 因果関係と併存の区別 |
| 疑い、否定、既往、家族歴 | 同じ病名でも文脈を混同しないこと |
| 詳細が未確定の入力 | 推測で確定せず、不足情報を返すこと |
| 廃止・変更されたコード | 入力版と出力版、置換根拠の追跡 |
| 候補複数・対応なし | 未対応を隠さず結果として返すこと |
| 入力にない属性を含む出力 | 根拠のない詳細化と、補助情報による追加を区別すること |
| 包含関係から導ける属性の明記 | 既存情報の明示化を、新たな臨床情報と数えないこと |
| 意味を取り込めないコード | 比較不能を差分なしと報告しないこと |
| 一度粗くした表現から別体系へ移行 | 出力単体での復元と、保持した原情報を利用する復元の区別 |

各例には入力体系・版・用途、原情報、期待候補、意味関係、喪失、追加と情報源、矛盾、比較不能の範囲、根拠、確認状態を添えています。実在患者の情報や、利用条件を未確認の外部コード表を置きません。

E16 件の期待結果も既に閲覧可能なので、未見性能の試験とは扱いません。主たる失敗機序のファミリーを分けて規則固定後に評価し、修正前後を記録します。設計固定後に未見の月次版を追加する手順と、期待結果の独立確認・凍結方法は [R4](../docs/research/04-evaluation.md) に定めています。実 CPC の部分追跡は Git 管理外に保存し、架空 40 件と分母を分けます。

[R1 の架空例](../docs/research/01-use-case.md) は用途と期待する監査内容の説明です。コードの定義・期待結果を確認した評価データとしてはまだ扱いません。
