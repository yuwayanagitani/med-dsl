# 実装の配置候補

まだパッケージや実装はありません。最終目標は [変化に原理的に耐えるコード体系の確立](../docs/vision.md) です。先に意味・拡張・互換性の原理を検討し、TypeScript 等の実装言語は試作範囲を決めてから選びます。

| ディレクトリ候補 | 責務 |
| --- | --- |
| `core/` | 体系の意味、拡張、不変条件、互換性の契約。具体的な分割は基礎調査後に検討 |
| `ast/` | 中間表現と変換結果の型・スキーマ |
| `ontology/` | 概念参照、関係、臨床知識モデルの境界 |
| `adapters/` | 外部マスターの取り込みと参照 |
| `compiler/` | 対応規則の適用、意味の喪失・追加と根拠の生成。監査部分を分けるかは今後検討 |
| `typechecker/` | 構造・意味制約・参照の検証 |
| `parser/` | 将来必要になった場合の DSL 構文解析 |
| `cli/` | 原理や中間用途の試作を検証する入口 |

最初からすべてを独立パッケージにせず、原理を検証する試作に必要な部分から配置します。移行用の接続先やライブラリの制約を、体系全体の表現能力に固定しません。
